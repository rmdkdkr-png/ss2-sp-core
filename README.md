# SS2 해설 엔진 + 레트로아크 코어

네오지오 포켓 컬러 『**사무라이 쇼다운!2**』에 한국어 해설·원버튼 필살기·일러스트 기둥을
얹는 엔진과, 그 엔진을 넣은 **Beetle NeoPop 포크 코어**입니다.

같은 엔진(`src/ss2comm.c`)이 코어·[안드로이드 앱](https://github.com/rmdkdkr-png/emu-ex-plus-alpha)·
브라우저 실행기에 그대로 들어갑니다.

> 안드로이드 앱만 쓰실 거라면 코어는 필요 없습니다 →
> [**NGPcustumSP 릴리즈**](https://github.com/rmdkdkr-png/CustumApKS)
>
> 다른 게임에는 아무 영향도 없습니다. 사쇼!2 가 아니면 SS2 층이 잠자코 있고
> 평범한 Beetle NeoPop 코어로 그대로 쓰실 수 있습니다.

---

## 1. 어느 파일을 받나

릴리즈에서 기기에 맞는 파일 **하나만** 받으시면 됩니다.

| 쓰시는 기기 | 파일 |
|---|---|
| **안드로이드 폰·태블릿** (요즘 기기 대부분) | `NGPcustumSP-core-v1.0.2-android-arm64-v8a.so` |
| 안드로이드 (오래된 32비트) | `…-android-armeabi-v7a.so` |
| 안드로이드 (에뮬레이터·일부 태블릿) | `…-android-x86_64.so` / `…-android-x86.so` |
| 안드로이드 (RISC-V) | `…-android-riscv64.so` |
| 리눅스 PC · 스팀덱 | `…-linux-x86_64.so` |

윈도우·ARM 리눅스 빌드는 아직 없습니다. 소스는 그대로 있으니 직접 빌드하실 수 있습니다(6장).

## 2. 넣는 곳

### 안드로이드 — 가장 쉬운 방법

파일 관리자를 만질 필요가 없습니다.

1. 받은 `.so` 를 폰의 **다운로드** 폴더에 둡니다
2. 레트로아크 → **Load Core** → **Install or Restore a Core**
3. 목록에서 그 파일을 고릅니다. 끝입니다

수동으로 넣으실 거라면 보통 이 경로입니다:

```
/storage/emulated/0/RetroArch/cores/
```

### 리눅스

```
~/.config/retroarch/cores/
~/.var/app/org.libretro.RetroArch/config/retroarch/cores/   ← 플랫팩
```

> **파일 이름을 바꾸셔야 할 수 있습니다.** 위 이름은 어느 기기용인지 구분하려고 붙인 것입니다.
> 넣을 때 `mednafen_ngp_libretro.so` 로 바꾸시면 기존 코어를 그대로 대체합니다.
> 기존 코어를 남겨 두고 싶으시면 `mednafen_ngp_ss2sp_libretro.so` 처럼 다른 이름으로 두십시오.

## 3. 코어 옵션

퀵 메뉴 → **Core Options**.

| 항목 | 기본값 | 값 |
|---|---|---|
| **SS2 One-button Specials** | Enabled | 원버튼 필살기 |
| **SS2 Character Commentary** | Enabled | 캐릭터 해설 |
| **SS2 Commentary Speaker** | Haohmaru | **15인 전원** |
| **SS2 Commentary Partner** | Enabled | 두 사람이 주고받는 대사 |
| **SS2 Commentary Display** | **Outside the screen, above** | 위 / 아래 / 화면 안 위 / 화면 안 아래 / 프론트엔드 알림 |
| **SS2 Side Art Pillars** | Enabled | 좌우 일러스트 기둥 |
| Language | english | 원래 있던 항목 |

기둥·해설 상태에 따라 화면 크기가 바뀝니다 — 전부 켜면 **288×184**,
전부 끄면 **160×152**(원본 그대로)입니다. 코어가 `SET_GEOMETRY` 로 알아서 보고합니다.

옵션과 게임 안 빠른 설정은 **양방향으로 이어져 있습니다.** 어느 쪽에서 바꿔도 서로 따라옵니다.

## 4. 버튼

NGPC 는 버튼이 A·B·Option 셋뿐입니다. 여기에 셋을 더합니다.

| 패드 | 하는 일 |
|---|---|
| B (아래) | **A** — 베기 |
| A (오른쪽) | **B** — 발차기 |
| **X** 또는 **R** | **SP** — 원버튼 필살기 |
| **Y** 또는 **L** | **A+B 동시** |
| **L2** | 해설자 교대 |
| Start | Option |
| **아래 + Start** | 빠른 설정 열기 / 닫기 |

### 필살기 = SP + 방향

SP 를 그냥 누르면 중립 자리, 방향을 같이 잡으면 그 자리 기술이 나갑니다.
자리는 일곱 — 기본 · →앞 · ←뒤 · ↓아래 · ↘ · ↙ · 공중.

**강하게 내려면 길게 누릅니다.** 트리거를 쥐고 있는 만큼 버튼이 유지됩니다.

### 비오의 = 뒤 + A+B

유파를 가리지 않습니다. 뒤를 잡지 않은 A+B 는 게임 원래 입력 그대로입니다.
(비오의는 분노 게이지가 차 있어야 나갑니다 — 원래 게임 규칙입니다.)

### SP 기술 배치

빠른 설정 → **SP 기술 배치**에서 캐릭터·유파를 고르고, 일곱 자리마다
**A 로 기술 목록에서** 고릅니다. 커맨드는 화살표로 보여 줍니다(`↓↘→ + A`).
공중 전용기는 `(공중)` 이 붙고, 지상 자리에 두면 커맨드 뒤에 `↗+버튼` 을 자동으로 넣어
**저공에서 나갑니다.** 「기본 배치로 되돌리기」도 있습니다.

B 는 한 겹씩 돌아갑니다: 기술 고르기 → SP 배치 → 빠른 설정 → 닫기.

### SP 를 눌렀는데 아무것도 안 나갈 때

| 상황 | 하는 일 |
|---|---|
| 그 방향 자리가 비어 있음 | **기본 자리 기술**로 대신 나갑니다 |
| 기본 자리까지 비어 있음 | 아무 입력도 내지 않고 「이 자리엔 기술이 없다」 한 줄 |
| 카드 기술인데 카드 미장착 | **내지 않습니다.** 「카드가 없다」 한 줄 |

카드 기술을 그냥 내보내면 커맨드만 게임에 들어가 **엉뚱한 헛손질**이 나갑니다. 그래서 막습니다.

## 5. 무엇을 하는 물건인가

### 원버튼 필살기

사쇼!2 는 커맨드 판정이 인색합니다. `623` 을 정확히 넣는 것도 어렵지만,
더 성가신 건 **제대로 넣었는데 엉뚱한 기술이 나가는 경우**입니다.

롬을 뜯어보니 커맨드 판정 루틴이 입력 기록을 거꾸로 훑으면서 **안 맞는 입력은 건너뜁니다.**
그래서 직전 입력 찌꺼기가 남아 있으면 짧은 커맨드가 긴 커맨드를 가로챕니다.

버튼을 누른 프레임에 두 가지를 합니다.

1. 램에 **1바이트**를 써서 게임이 스스로 입력 기록을 정리하게 합니다 (게임 자신의 리셋 경로)
2. 현재 캐릭터·유파에 맞는 커맨드를, 보고 있는 방향에 맞춰 뒤집어 프레임 단위로 넣습니다

없는 기술을 만들어내거나 데이터를 고치지 않습니다. **입력만 대신 넣습니다.**
히트스톱이나 공중 판정도 게임 규칙 그대로 지킵니다.

**검증** — 네이티브 하네스에서 프레임 단위 재현 시험:

| | 결과 |
|---|---|
| 버튼 배치 — 중립 발동 · 뒤로 걷다가 발동 | **12 / 12** |
| 강/약 — 트리거 유지에 따른 버튼 유지 프레임 | 1f→6f · 8f→8f · 15f→15f · 30f→33f(상한) |
| SP 배치 — 5방향 × 중립·뒤걷기 | **15 / 15** |
| 커맨드 하이재킹 (7종 × 6회) | 무보정 0/42 → **41/42** |
| 3연참 연속 입력 손상 | 없음 (3/3) |

### 해설

**15인 전원**이 각자 말투로 경기를 읽습니다. 심판 **쿠로코**가 판정을 외칩니다.
대사는 **4,200여 줄** — 상대 이름을 부르는 반응, 관계 대사, 라운드 사이, 경기 후 전적과
설욕, 메뉴 화면 사담까지 들어 있습니다. 두 사람이 주고받는 대사도 있습니다(파트너 옵션).

**표시 자리**를 고를 수 있습니다.

- `Outside the screen` (기본값 **위**) — 게임 화면 밖에 **32픽셀 띠**를 붙입니다.
  게임 화면을 한 픽셀도 가리지 않습니다. 대신 그림 세로가 152 → 184 로 늘어납니다
- `Inside the screen` — 화면 크기·비율을 **원래대로 두고** 게임 화면 안에 말풍선을 그립니다
- `Frontend notification only` — 레트로아크 알림으로 넘깁니다
  (프론트엔드 글꼴에 한글이 없으면 깨질 수 있습니다)

글꼴은 코어가 들고 있는 **갈무리 11px 좁은꼴**이고, 화자의 얼굴도 함께 나옵니다.

### 일러스트 기둥

화면 좌우에 **64픽셀 기둥**을 세우고 대전 상대의 카드 대형 일러를 그립니다.
캐릭터가 기둥에 설 때 변형 4장 중 하나를 정해 내려갈 때까지 유지합니다.

경기 상황이 기둥에 실립니다 — 맞은 쪽이 피해량에 비례해 **흔들리고**, 강타는 **백섬광**,
빈사면 **붉게**, KO 순간 진 쪽은 **흑백**이 됩니다.

### 그림은 배포물에 없습니다

일러스트도 초상화도 코어에 들어 있지 않습니다. 코어가 들고 있는 것은 **타일 주소표와
팔레트 번호, 검증합**뿐이고, 그림은 실행 중 **당신의 롬에서 그 자리에서 구워집니다.**
롬이 없으면 아무 그림도 안 나옵니다. 검증합이 안 맞는 다른 판본 롬이면 조용히 생략됩니다.

## 6. 직접 빌드하기

이 저장소에 **코어 전체 소스가 들어 있습니다.** 패치를 받아 얹는 구조가 아닙니다.

```bash
# 리눅스 x86_64
cd build && make -f Makefile -j4
#   → build/mednafen_ngp_libretro.so

# 안드로이드 5개 ABI 전부
"$ANDROID_NDK_ROOT/ndk-build" \
  NDK_PROJECT_PATH="$PWD/build" \
  APP_BUILD_SCRIPT="$PWD/build/jni/Android.mk" \
  NDK_APPLICATION_MK="$PWD/build/jni/Application.mk" -j4
#   → build/libs/{arm64-v8a,armeabi-v7a,riscv64,x86,x86_64}/libretro.so
```

경로는 **절대경로로** 주십시오. 상대경로면 ndk-build 가 `jni/jni/…` 를 찾다 실패합니다.

> ⚠️ **make 가 헤더 의존성을 추적하지 않습니다.** `ss2comm_lines.h` · `ss2sp_moves.h` 같은
> 헤더만 고쳤다면 `.o` 가 그대로 남아 옛 코드가 링크됩니다. 헤더를 손댔으면
> `rm -f build/ss2comm.o build/ss2sp.o build/libretro.o` 하고 다시 빌드하십시오.
> ndk-build 는 의존성을 추적하므로 이 문제가 없습니다.

빌드한 코어가 어느 커밋인지는 `retro_get_system_info` 의 버전 문자열에 찍힙니다
(`v1.29.0.0 · SS2 v0.6 <커밋>`). 6종이 전부 같은 커밋인지 여기서 확인하실 수 있습니다.

### SS2 층이 사는 곳

| 파일 | 내용 |
|---|---|
| `src/ss2comm.c` · `.h` | 해설 엔진 본체 — 램만 읽어 이벤트를 잡고 대사를 고르고 그린다. 기둥·오버레이도 여기 |
| `src/ss2comm_lines.h` | 대사표 (자동 생성 — `tools/gen_lines.js`) |
| `src/ss2comm_art.h` | 일러스트 타일 주소표 (그림 없음) |
| `src/ss2comm_font.h` · `_font11.h` | 갈무리 글리프 909자 8×8 / 11px (OFL, 자동 생성) |
| `src/ss2sp.c` | 원버튼 엔진 — 프레임 큐, 커맨드 컴파일, 히트스톱·착지 게이트 |
| `src/ss2sp_moves.h` | 기술표 — 15캐릭터 / 30유파, SP+방향 기본 배치 포함 |
| `build/libretro.c` | 엔진 호출 · 코어 옵션 7개 · 와이드 합성 · 오버레이 입력 라우팅 |

`src/` 가 원본이고 `build/` 로 복사해 넣습니다. 앱 쪽으로 보낼 때는
`#include "ss2comm.h"` 를 `#include <ss2comm/ss2comm.h>` 로 바꿔 넣습니다.
