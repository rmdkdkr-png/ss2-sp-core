# SS2 원버튼 코어 — 레트로아크용

『사무라이 스피리츠! 2』(NGPC)의 **필살기를 버튼 하나로** 내주는 기능을
에뮬레이터 코어 자체에 넣은 것입니다. Beetle NeoPop 포크입니다.

브라우저 실행기와 같은 엔진이지만, 이건 **레트로아크(RetroArch)에서 그대로 돌아갑니다.**
안드로이드 폰, 휴대용 게임기, PC — 레트로아크가 도는 곳이면 됩니다.

> 📖 **설치·설정을 화면 그대로 따라가려면 [설정 설명서](https://rmdkdkr-png.github.io/ss2-sp-runner/docs/setup-guide.html) 를 여세요.**
> 롬이 목록에 안 보일 때, 강/약 내는 법, 버튼 다시 매핑까지 항목별로 적어 두었습니다.

> 다른 게임에는 아무 영향도 주지 않습니다. 사쇼!2가 아니면 엔진이 그냥 잠자코 있습니다.
> 평범한 Beetle NeoPop 코어로 쓰셔도 됩니다.

## 1. 어느 파일을 받아야 하나

| 쓰시는 기기 | 파일 |
|---|---|
| **안드로이드 폰·태블릿** (요즘 기기 대부분) | `mednafen_ngp_libretro.android-arm64-v8a.so` |
| 안드로이드 (오래된 32비트) | `mednafen_ngp_libretro.android-armeabi-v7a.so` |
| **윈도우 PC** | `mednafen_ngp_libretro.windows-x86_64.dll` |
| 리눅스 PC · 스팀덱 | `mednafen_ngp_libretro.linux-x86_64.so` |
| ARM 리눅스 휴대기기 (Anbernic 등) | `mednafen_ngp_libretro.linux-aarch64.so` |

> ⚠️ **안드로이드 코어는 여기 미리 넣어 두지 못했습니다.**
> 빌드에 안드로이드 NDK가 필요한데 작업 환경에서 내려받을 수 없습니다(구글 배포처가 막혀 있습니다).
> 대신 **GitHub Actions 워크플로**가 들어 있습니다. 러너에는 NDK가 이미 깔려 있어 그냥 됩니다.
>
> 1. 이 저장소를 올린다(덮어쓰기)
> 2. **Actions** 탭 → 왼쪽에서 **build cores** → 오른쪽 **Run workflow** → 초록 버튼
> 3. 몇 분 뒤 그 실행 화면 아래 **Artifacts → cores-android** 를 받는다
> 4. 압축을 풀면 `mednafen_ngp_libretro.android-arm64-v8a.so` 가 들어 있다 (요즘 폰은 이것)
>
> 무료이고, 워크플로는 여기 소스(해설 엔진 포함)를 그대로 써서 빌드합니다.
> 직접 빌드하시려면 `bash build.sh android-arm64` (ANDROID_NDK_ROOT 필요).

> 리눅스 x86_64 · 리눅스 aarch64 · 윈도우 코어는 **이 저장소에 최신으로 들어 있습니다**
> (해설 v0.4.12 반영, `cores/` 폴더).

## 2. 넣는 곳

### 안드로이드 — 가장 쉬운 방법

레트로아크 안에서 바로 설치할 수 있어 파일 관리자를 만질 필요가 없습니다.

1. 받은 `.so` 파일을 폰의 **다운로드** 폴더에 둡니다.
2. 레트로아크 → **Load Core** → **Install or Restore a Core**
3. 목록에서 그 파일을 고릅니다. 끝입니다.

수동으로 넣으실 거라면 경로는 보통 이곳입니다:

```
/storage/emulated/0/RetroArch/cores/
```

### 윈도우

```
RetroArch\cores\mednafen_ngp_libretro.dll
```

`.info` 파일도 같이 넣으시면 메뉴에 이름이 예쁘게 나옵니다:

```
RetroArch\info\mednafen_ngp_libretro.info
```

### 리눅스

```
~/.config/retroarch/cores/          (또는 ~/.var/app/org.libretro.RetroArch/config/retroarch/cores/  ← 플랫팩)
~/.config/retroarch/info/
```

> **파일 이름을 바꿔야 할 수도 있습니다.** 위 표의 파일명은 어떤 기기용인지 구분하려고 붙인 것입니다.
> 넣을 때는 플랫폼별 기본 이름(`mednafen_ngp_libretro.so` / `.dll`)으로 바꾸시면
> 기존 코어를 그대로 대체합니다. 기존 코어를 남겨 두고 싶으시면
> `mednafen_ngp_ss2sp_libretro.so` 처럼 다른 이름으로 두셔도 됩니다.

## 3. 켜는 법

롬을 이 코어로 실행한 다음:

**퀵 메뉴 → 옵션(Core Options)**

| 항목 | 값 |
|---|---|
| **SS2 One-button Specials** | `Enabled` (기본값) |
| **SS2 Character Commentary** | `Enabled` (기본값) — 캐릭터가 경기를 해설합니다 |
| **SS2 Commentary Speaker** | `Haohmaru` / `Nakoruru` / `Hanzo` / `Galford` |
| **SS2 Commentary Display** | `Outside the screen, below` (기본값) / `above` / `Inside the screen, bottom` / `top` / `Frontend notification only` |

`Language` 는 원래 있던 항목입니다. 한글 패치본은 일본어로 두시면 됩니다.

### 해설이란

브라우저 실행기에 있던 **캐릭터 해설**을 코어에 옮겨 놓은 것입니다.
하오마루·나코루루·한조·갈포드 중 한 명이 경기를 지켜보며 한 줄씩 던집니다.
**이벤트 52종 · 대사 400여 줄** — 브라우저판과 같은 대사표를 그대로 씁니다.

- **경기 전** 매치업 호명, 화자와 상대의 **관계 대사**(하오마루→겐주로, 나코루루→리무루루 …),
  없으면 그 캐릭터 설정 한 줄
- **경기 중** 필살기 적중·다운·KO(SP로 낸 기술은 **이름까지** 부릅니다), 선제타, 큰 한 방,
  피격, 상대 필살기 경고, 반피·벼랑끝, 역전, 장기전, 정적
- **라운드 사이** 선취·열세·매치포인트
- **경기 후** 승패 화면 반응 + 한마디 더, **오늘 전적**, **설욕**(직전에 진 상대를 다시 이겼을 때),
  세션 연승, 무한대전 연승·결산, 스토리 진행
- **메뉴에서** 타이틀·캐릭터선택·유파선택·카드 화면 멘트, 고르는 동안의 사담,
  오래 머무를 때 한마디, 자동으로 넘어가는 스토리 화면 사담, 그리고 조용할 때의 혼잣말

기술 이름은 **SP 버튼으로 낸 기술**만 부릅니다 — 그 표는 코어가 들고 있어 롬 버전과 무관합니다.
손 커맨드로 낸 기술이나 상대 기술은 이름 없이 반응합니다.

**표시 자리**를 고를 수 있습니다.

- `Outside the screen` (기본값, 아래/위) — 게임 화면 **밖에 30픽셀 띠**를 붙이고 거기에 그립니다.
  게임 화면을 한 픽셀도 가리지 않습니다. 글꼴은 코어가 들고 있는 **갈무리11 좁은꼴 11px**이고
  화자의 얼굴도 함께 나옵니다. 대신 그림 세로가 152 → 182로 늘어납니다(비율도 맞춰 보고합니다).
- `Inside the screen` (아래/위) — 화면 크기·비율을 **원래대로(160×152) 두고** 게임 화면 안에
  말풍선을 그립니다. 대사가 뜨는 2.5초 동안만 화면 일부가 가려집니다.
  화면비가 바뀌는 게 싫을 때 쓰십시오.
- `Frontend notification only` — 코어는 그리지 않고 레트로아크 알림으로 넘깁니다.
  프론트엔드 글꼴에 한글이 없으면 깨질 수 있습니다.

해설이 필요 없으면 **SS2 Character Commentary** 를 `Disabled` 로 두십시오.

### 얼굴 · 글자 · 연출

코어가 직접 그리는 모드에서는 브라우저 실행기와 같은 연출이 붙습니다.

- **얼굴** — 화자의 초상이 띠(또는 말풍선) 왼쪽에 16×16으로 나옵니다.
  그림은 **배포물에 들어 있지 않습니다.** 코어가 **당신의 롬에서 그 자리에서 그립니다**
  (전투 HUD 초상 타일의 롬 오프셋만 숫자로 들고 있습니다. 64바이트 검사합이 안 맞는
  다른 버전 롬이면 얼굴은 조용히 생략되고 글자만 나옵니다).
- **표정** — 이벤트에 따라 얼굴빛이 바뀝니다. 이겼을 때는 밝아지며 까딱이고,
  몰렸을 때는 어두워지며 떨립니다.
- **글자** — 갈무리11 좁은꼴 11px 로 크게, 한 글자씩 찍혀 나옵니다(프레임당 두 자).
  높이는 11픽셀이면서 폭이 8픽셀이라 한 줄에 스무 자가 들어갑니다 — 대부분의 대사가 한 줄에 끝납니다.
  게임 화면 위에서도 읽히도록 글자마다 그림자를 한 겹 깔았습니다.
  KO·완승·역전·속공·연승·엔딩 같은 **한 방짜리 대사는 굵은 금색**으로 나오고,
  상자가 한 번 붉게 번쩍입니다. 긴 대사는 두세 줄로 접힙니다.
- 띠는 높이가 30픽셀 고정이라 큰 글씨 두 줄까지입니다. 아주 긴 대사는 자동으로
  작은 글씨(8px) 두 줄로 접혀 잘리지 않습니다. 화면 안 말풍선은 대사 길이에 맞춰 늘어납니다.

## 4. 버튼 — 넷뿐입니다

NGPC는 버튼이 A·B·Option 셋뿐입니다. 여기에 둘을 더해 **네 개**로 끝냅니다.

| 패드 | 하는 일 |
|---|---|
| B (아래) | **A** — 베기 |
| A (오른쪽) | **B** — 발차기 |
| **Y** (또는 L) | **A+B 동시** |
| **X** (또는 R) | **SP** — 필살기 |
| Start | Option |

### 필살기 = SP + 방향

SP 를 그냥 누르면 중립 자리, 방향을 같이 잡으면 그 자리의 기술이 나갑니다.
자리는 일곱입니다 — 중립 · 앞 · 뒤 · 아래 · ↘ · ↙ · 공중(↑).
어느 기술을 어느 자리에 둘지는 **기술 배치**에서 바꿉니다(브라우저 실행기·앱에서 편집,
코어는 기본 배치로 돕니다).

### 비오의 = 뒤 + A+B

유파를 가리지 않고 **뒤를 잡은 채 A+B**입니다. 뒤를 잡지 않은 A+B 는 게임 원래 입력 그대로입니다.
(비오의는 분노 게이지가 차 있어야 나갑니다 — 원래 게임 규칙입니다.)

> 예전 판에 있던 SP2~SP8 버튼은 없앴습니다. 옛 설정이 남아 있어도 눌러봐야 아무 일도 없습니다.

### SP를 눌렀는데 아무것도 안 나갈 때

두 가지 경우가 있고, 코어가 서로 다르게 처리합니다.

| 상황 | 하는 일 |
|---|---|
| 그 방향 자리에 기술을 안 둠 | **중립 자리 기술**로 대신 나갑니다 |
| 중립까지 비어 있음 | 아무 입력도 내지 않고 "이 자리엔 기술이 없다" 한 줄 |
| 카드 기술인데 카드 미장착 | **내지 않습니다.** "카드가 없다 — 그 기술은 못 낸다" 한 줄 |

카드 기술을 그냥 내보내면 커맨드만 게임에 들어가 **엉뚱한 약/강베기(헛손질)** 가 나갑니다.
그래서 아예 막습니다. 안내 한 줄은 해설과 같은 자리에 뜹니다(해설을 꺼 두면 조용히 넘어갑니다).

### 강하게 내려면 — 길게 누릅니다

## 5. 무엇을 하는 물건인가

사쇼!2는 커맨드 판정이 인색합니다. `623` 을 십자키로 정확히 넣는 것도 어렵지만,
더 성가신 건 **제대로 넣었는데 엉뚱한 기술이 나가는 경우**입니다.

롬을 뜯어보니 커맨드 판정 루틴이 입력 기록을 거꾸로 훑으면서
**안 맞는 입력은 건너뜁니다.** 그래서 직전 입력 찌꺼기가 남아 있으면
짧은 커맨드가 긴 커맨드를 가로챕니다.

이 코어는 버튼을 누른 프레임에 두 가지를 합니다.

1. 램에 **1바이트**를 써서 게임이 스스로 입력 기록을 정리하게 합니다 (게임 자신의 리셋 경로).
2. 현재 캐릭터·유파에 맞는 커맨드를, 보고 있는 방향에 맞춰 뒤집어 프레임 단위로 넣습니다.

없는 기술을 만들어내거나 데이터를 고치지 않습니다. **입력만 대신 넣습니다.**
히트스톱(맞고 있는 중)이나 공중 판정도 게임 규칙 그대로 지킵니다.

### 검증

네이티브 하네스에서 프레임 단위로 재현 시험한 결과입니다.

| | 결과 |
|---|---|
| 버튼 배치 — 중립 발동 · 뒤로 걷다가 발동 | **12 / 12** |
| 강/약 — 트리거 유지에 따른 버튼 유지 프레임 | 1f→6f · 8f→8f · 15f→15f · 30f→33f(상한) |
| SP 배치 — 5방향 × 중립·뒤걷기 | **15 / 15** |
| 커맨드 하이재킹 (7종 × 6회) | 무보정 0/42 → **41/42** |
| 3연참 연속 입력 손상 | 없음 (3/3) |

## 6. 직접 빌드하기

```bash
./build.sh                    # 리눅스 x86_64 (호스트)
./build.sh linux-aarch64      # ARM 리눅스
./build.sh windows-x86_64     # 윈도우 DLL
./build.sh android-arm64      # 안드로이드 (ANDROID_NDK_ROOT 필요)
```

필요한 크로스 컴파일러:

```bash
sudo apt install gcc-aarch64-linux-gnu g++-aarch64-linux-gnu \
                 gcc-mingw-w64-x86-64 g++-mingw-w64-x86-64
```

스크립트가 upstream(`beetle-ngp-libretro`, 커밋 `a50d5ac`)을 받아
`src/ss2sp.patch` 를 적용하고 `src/ss2sp.c` 를 얹어 빌드합니다.

### 손댄 곳은 네 군데뿐입니다

| 파일 | 내용 |
|---|---|
| `ss2sp.c` | 원버튼 엔진 본체 — 프레임 큐, 커맨드 컴파일, 히트스톱·착지 게이트 |
| `ss2sp_moves.h` | 기술표 — 15캐릭터 / 30유파 / 171기술, SP+방향 기본 배치 157자리 포함 |
| `ss2comm.c` · `ss2comm.h` | 해설 엔진 — 램만 읽어 이벤트를 잡고 대사를 고른다. 표시까지 여기서 한다 |
| `ss2comm_font.h` | 대사에 쓰이는 글자만 뽑은 8×8 갈무리 글리프 323자 (OFL) |
| `libretro.c` | `update_input()` 끝에 엔진 호출 + `retro_run()` 에 해설 호출 + 코어 옵션 5개 |
| `Makefile.common` | `ss2sp.c` · `ss2comm.c` 두 줄 추가 |

`ss2sp_moves.h` 를 다시 만드셨다면 **`ss2sp.o` 를 직접 지우셔야 합니다.**
make 가 헤더 의존성을 추적하지 않습니다.
