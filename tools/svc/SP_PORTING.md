# SP 원버튼 엔진 — 타 게임 이식 안내서 (KOF R2 · Fatal Fury FC · SS1 · SS2)

2026-09-02. SVC MotM 에서 완성한 원버튼 필살기 엔진을 다른 NGPC 격투게임으로 옮기는
방(세션)을 위한 자족 문서다. **이 문서만 읽고 시작할 수 있게** 적는다.
SVC 쪽 전말은 `HANDOVER.md`(같은 폴더), 실측 상세는 `SVC_MEMO.md`.

---

## 0. 무엇을 옮기는가

**코드는 안 옮겨진다. 방법론과 도구가 옮겨진다.**
엔진의 모든 마법은 게임별 램 지도에 박혀 있다 — SVC 기준:

| 상태 | SVC 주소 | 쓰임 |
|---|---|---|
| P1 동작 ID (act) | 0x0968 | 기술 신원의 유일 잣대. 캐릭터별 네임스페이스 |
| 방향 입력 이력 링 | 0x0CB8~0x0CCE (stride 2, 최신 0x0CC8, 수명 ~16f) | **링 주입** = 커맨드를 이력에 직접 써서 발동 9→3f |
| 버튼 홀드 카운터 | 0x0C76(P)/0x0C77(K), 2f당 +1, ++==문턱에서 강 래치 | **즉발 주입** = 문턱−1을 박아 강을 2~3f에 |
| 동작 카운터 | 0x0C7E(P)/0x0C7F(K), 2f당 +1, 127 포화 | 행동가능 근사(둘 다 ≥6). ⚠️발동 없이도 리셋됨 — 성공신호로 쓰지 마라 |
| 롬 강약 문턱 | 롬 0x000D4E (원본 4) | 게임의 강 판정 길이. 건드리면 공중강 죽음(실측) |
| P2 반응 | 0x0AC4 (255=피격경직) | 히트 판정. hp 열은 표시 지연 있음 |
| 콤보 카운터 | 0x0B17 | 콤보 성립 판정 |
| 좌우 | 0x092C bit7 | 좌표 비교 금지(사냥 함정 §3) |

이식 = **이 표를 대상 게임에서 다시 채우는 것**. 채우면 svcsp.c 의 구조(슬롯 해석 →
컴파일 → 링 주입/즉발 주입 → 파생/착지/모으기 게이트)가 거의 그대로 산다.

## 1. 게임별 출발점

- **KOF R2**: 한글패치 v0.2 릴리즈 존재(KrPatch `kofr2-v0.2`). SVC 와 같은 SNK 격투
  계보라 램 구조가 닮았을 **가능성**(미확인 — 같은 주소부터 찔러보되 맹신 금지).
- **Fatal Fury FC**: 한글패치 릴리즈 존재(`ffc-v0.1a`).
- **SS1**: 한글패치 릴리즈 존재(`ss1-v0.19`).
- **SS2**: ⚠️ 사정이 다르다 — 이미 원버튼이 있다(게임 내장 간이입력 ABLE 을 ss2sp 가
  사용, `src/ss2sp.c`). SVC식 링 주입으로 더 조이는 것은 별도 수요 판단 후.

## 2. 작업 순서 (SVC 에서 검증된 경로)

1. **하네스 확보**: `~/ss2/repo/ss2-main/tools/svc/svcrun.c` 를 복제·개조. 대본 문법:
   `<프레임수> <버튼|->`, `!load <st>`, `!poke <hex>=<dec>`, `!w <tag>@<n>`(CSV 프로브),
   `!<tag>`(RAM 16KB + PPM 화면 덤프). CSV 오프셋 표를 대상 게임 것으로 교체한다.
   ⚠️ 대본 버튼 문자는 레트로패드: **B=약펀 A=약킥 Y=강펀 X=강킥**(코어 리맵 기준),
   L/R/U/D=방향. 약버튼은 6f 강제해제(약컷) — 강 지문은 Y/X 로 채집할 것.
2. **정지 무대 세이브**: 스파링/연습 모드에서 「적동작=정지」 상태를 캐릭터×위상(2종)별로.
   SVC는 `~/ss2/saves/svc/svc_ct_정지_<캐릭id>_<위상>.st`. 아케이드 무대는 CPU가
   반격해서 콤보 실측 무효(실측). 대사 중엔 입력이 안 먹으니 스킵까지 밀어 굽는다.
3. **램 사냥** (전부 diff 로):
   - act: 같은 조건 두 번 돌려 노이즈 제거 후, 기술별로 달라지는 바이트.
   - 이력 링: 방향을 누르며 램 diff — 방향 비트값이 미끄러져 내려가는 창.
   - 홀드 카운터: 버튼을 쥐고 2f당 +1 오르다 놓으면 리셋되는 바이트.
   - 모으기(차지): ⚠️ SVC 가일의 차지 내부 상태는 **끝내 못 찾았다**(카운터 후보·래치
     후보·링 위조 전부 주입 실패). 엔진은 상태를 흉내내지 않고 **사용자의 실제 홀드를
     게이트로 판정**(문턱·유예는 원거리 실측으로) — 이 방식이 이식하기도 쉽다.
4. **act 카탈로그**: 기본기 12종(서서/앉아×약강×손발)+점프+기술을 한 번씩 발동시켜
   act 번호표를 만든다(land7.sh A절 패턴). 이게 이후 모든 판정의 잣대다.
5. **엔진 이식**: svcsp.c 를 복제해 오프셋/기술표(moves.json→gen_svc_moves.py)만 교체.
   기술표는 커맨드·버튼·kind(special/super)·모으기 `[n]` 표기·강판 name_hold·파생 next.
6. **검증 배터리**: 아래 §4 원칙으로 스크립트를 짜서 전 항목 녹색 후에만 배포.

## 3. 사냥 함정 (전부 실제로 밟은 것 — SVC_MEMO·HANDOVER 에 상세)

- **act 는 캐릭터별 + 진행 위상 분화**(가일 붐 = 2/37/38/48). 중립 집합(0·21·22·23·255도
  게임마다 다름)을 캐릭터별로 재검증. **act 단독으로 신원 확정 금지** — 픽셀·react·원거리로 교차.
- **투사체는 원거리에서만 규명**. 근접은 몸타와 구분 불가 — 이걸 어겨서 가짜 발견
  (x좌표 포크 즉발)을 하루 배포까지 갔다 회수했다.
- **탐색 루프(이분법·ddmin)를 돌리기 전에 성공 판정식부터 검증**. 판정이 오염되면
  이분법은 그럴듯한 엉뚱한 바이트에 수렴한다(실화: P1 X좌표를 차지 상태로 오인).
- 동작 카운터 리셋·뱅크(0x09AD류)·피해량은 성공/신원 신호로 **금지**(전부 오판 전과).
- 하네스 CSV 의 좌표 열은 8/16비트 랩 주의(p2x 142=398 사건). 반전 판정은 face 플래그로.
- 2프레임 입력 샘플링 — **모든 실측은 위상 2종**(선행 프레임 홀짝)으로.
- PowerShell 인라인 금지(경로·$ 확장 사고 전과) — 스크립트 파일 + 절대경로.
- 빌드 후 sleep 2~3, 코어 두 벌 함정(SVC=svc-core 워크트리 / SS2=main) 주의.

## 4. 검증 원칙 (판정 사다리 — 이 방의 헌법)

1. 실험 **전에** 성공/실패 판정식을 숫자로 선고정. 출력 보고 기준 변경 금지.
2. 판정은 원시 CSV 3층: 발동=act 진입 프레임 / 히트=react(255) 프레임 / 콤보=그 프레임 combo≥2.
3. 매 배치에 양성·음성 대조군 — 어긋나면 배치 전체 무효(측정기 고장 탐지).
4. "됐다"는 위상 2종 재현 + 회귀 통과 후에만. 가부 보고엔 사진(PPM→PNG).
5. "나가면 안 되는" 음성 케이스를 반드시 포함(연타 누수·유령 파생·유예 밖 거부).
6. 판독 오버레이(SVCSP_ACTSHOW 패턴: 좌상단 「내 act|상대 react」)를 이식 첫 주에 넣어라 —
   이후 실기 영상이 곧 판정이 된다.

## 5. 엔진 구조 요약 (svcsp.c 에서 가져올 것)

- **슬롯**: N/F/B/D/DF/DB/AIR + ORDER 흐름(빈자리 인접 이동). **비움 = 완전 무반응**(0 반환).
- **컴파일**: 이력 링 주입(비모으기, len 2~8) + 마지막 방향+버튼 동시 스텝. 강약 = SP 홀드
  미러링(탭=약 / 12f+=강. 링 주입 시 경계 8). 강판 없는 기술은 약 상한에서 끊기(불발 방지).
- **파생(렛카)**: 창은 매크로 끝 +34f, 발사는 「부모 발동 act 증거」+「기술 진행 중 입력」
  2겹 게이트. 모으기·파생은 재시도 금지. retry 성공판정은 act 증거(뱅크는 위상 오판).
- **착지 선입력**: 엣지 사이클(3f누름+2f뗌×36f, 성공감지 act) — 게임이 행동가능 3~4f 전
  엣지만 버퍼하기 때문. 공중 소비 감지(버튼 하나=기술 하나).
- **모으기**: 게이트 = 잡은채(비트 포함, ↙는 뒤·아래 겸용) 또는 기억+유예(SVC 실측: 문턱
  30f·유예 8f — 게임마다 재실측). 마무리(방향+버튼 동시)만 큐잉. 강판 = name_hold 등록
  + 버튼스텝 카운터 주입(기술키 4f+ 유지 시).
