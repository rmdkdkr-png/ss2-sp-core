# SvC MotM 정찰 결과 (scratchpad 전용 — 커밋 안 함)

대상: SNK vs. Capcom MotM (NGPC), 한글패치 v17.2 (헤더 `SNKvsCAPCOM1`, 4MB)

## 1. 시험대

- 하네스 `svcrun.c` — 입력 스크립트 + 램/화면 덤프 + **상태 저장·복원**
  - 스크립트 문법: `<프레임> <버튼…>` / `!태그`(덤프) / `!save 파일` / `!load 파일`
  - 버튼: U D L R A B X Y ST SE  — **NGP A = 레트로 B**, NGP B = 레트로 A
- **전투 기준 상태 `svc_f2.st`** — 쿄(균형) vs 춘리, 도톤보리, 타이머 56
- 메뉴 경로: 타이틀 → 시작하기 → 메인메뉴(토너먼트) → 게임선택(싱글)
  → **유파선택(반격/균형/속공)** → 캐릭터선택 → VS → 스테이지 → 전투

## 2. ★ 원버튼은 된다 — 그리고 SS2 보다 쉽다

- **커맨드 주입으로 필살기가 나온다.** 236+A → 불꽃, 623+A → 상승기.
- **가로채기 문제가 없다.** SS2 의 핵심 난관이던 「찌꺼기가 긴 커맨드를 가로챔」이
  SvC 엔 없다. 네 가지로 확인:

  | 시험 | 결과 |
  |---|---|
  | 236 찌꺼기 남기고 → 623+A | **623+A 나감** (가로채기 없음) |
  | 236 찌꺼기 + 2f 후 → 623+A | 623+A 나감 |
  | 623 앞부분 남기고 → 236+A | 236+A 나감 |
  | 623 모션(버튼 없이) 후 → 236+A | 236+A 나감 |

  → **SS2 의 램 리셋 트릭이 필요 없다.** 입력만 넣으면 된다.

- **커맨드 입력 간격 창 = 2~4 프레임.**
  1프레임(너무 빠름) · 5프레임 이상(시간 초과) 은 실패. SS2 보다 창이 좁다.
- 직전 입력 찌꺼기(뒤로걷기·앞걷기·평타·아래·앞아래·웅크림)는 전부 정상 발동.
  실패했던 「B평타 직후」「점프 직후」는 **경직 때문**이었고 40프레임 기다리면 나간다.
  → 엔진은 「지금 행동 가능한가」만 보면 된다.

## 3. RAM 오프셋 (SYSTEM_RAM 16KB, CPU주소 = 0x4000 + 오프셋)

| 오프셋 | 뜻 | 값 | 근거 |
|---|---|---|---|
| `0x08A0` | **P1 캐릭터 ID** | 쿄=0, 테리=1, 켄=12 | 캐릭터 3종 교차검증 (사본 0x0882·0x096D) |
| `0x08BE` | **P1 유파** | 반격=0, 균형=1, 속공=2 | 유파 3종 전부 다른 값 (사본 0x096E) |
| `0x08CF` | **P2 체력** (최대 48) | 한 방에 48→47 | 체력바 오른쪽 끝과 일치 (사본 0x08D3) |
| `0x08EE` | 라운드 타이머 (10진) | 58/56/54 | 화면 숫자와 일치 |
| `0x092E` | P1 화면 X | | 입력 방향대로 R>무>L (사본 0x243E) |
| `0x0934` | P2 화면 X | 기준 94 | 카메라 스크롤 같이 탐 |
| `0x09AD` | P1 애니메이션 뱅크 | 236+A=22, 623+A=23, 지상평타·대기=255 | **발동 판정에 쓸 수 있다** |
| `0x0C7E` | P1 애니 카운터 | 동작 시작 0 → 증가, 대기 127 | 기술 종류와 무관 (사본 0x0C86) |

- **방향은 따로 안 찾아도 된다** — `P1X < P2X` 면 오른쪽. 커맨드 미러링엔 충분.
- 0x09AD 는 점프 중에도 255 가 아니다(=6). 「필살기 여부」로 쓰려면 지상 여부와 함께 봐야 한다.

## 4. 아직 못 한 것

- ~~P1 체력~~ — **해결 (12장).** 0x08AF·0x08B3 쌍. 0x08D0/0x08D1 은 상수(둘 다 아님).
- 기술 고유 ID (0x09AD 는 애니 뱅크라 기술마다 유일하지 않을 수 있음)
- 히트스톱 · 공중 판정
- 26명 기술표 (지금은 쿄 236/623 만 실측)


## 6. ABLE — 이 롬엔 없다 (실측 결론)

게임 내 BATTLE CONFIG 항목은 **DISP CUT / ADVANTAGE / PROVOKE / BUTTON / WINNING POINT**
다섯뿐이다 (유저 실기 확인). ABLE 같은 간이입력 설정은 없다.

혹시 유파가 커맨드를 간략화하는가 싶어 **세 유파 전부에서** 재봤다 — 아니다.

| 입력 | 반격 | 균형 | 속공 |
|---|---|---|---|
| ↓↘→+P (정식) | 발동 | 발동 | 발동 |
| →+P | — | — | — |
| ←+P | — | — | — |
| ↓+P | — | — | — |
| ↓+K | — | — | — |
| →+K | 특수기(굉부양) | 〃 | 〃 |

→ **간이 커맨드는 존재하지 않는다. 정식 커맨드만 먹는다.**
   FAQ 의 ABLE 열은 이 판본과 대응하지 않으므로 기술표 작성에 쓰지 않는다.
   버튼 배치는 **A=PUNCH, B=KICK** (게임 설정 화면 확인).

**뒤집어 보면 좋은 소식이다** — 이 게임엔 간이입력이 없으니
우리 원버튼 SP 가 대체재가 아니라 **이 게임 최초의 간이입력**이 된다.

## 7. 입력 규칙 (실측)

- **마지막 방향을 버튼보다 먼저 잡아야 한다.** →와 버튼을 같은 프레임에 넣으면 실패.
  방향을 2~4프레임 유지한 뒤, 그 방향을 **유지한 채로** 버튼을 누른다.
- 방향 간 간격 2~4프레임. 1프레임(너무 빠름)·5프레임 이상(시간 초과)은 실패.

## 8. 쿄 실측 표 (균형, 진행 중)

| 입력 | 0x09AD | 데미지 | 판정 |
|---|---|---|---|
| ↓↘→+P | 22 | 1 | 114식 황물기 — 가이드와 일치 |
| ↓↘→+K | 22 | 0 | 나가지만 빗나감 |
| ↘+K | 21 | **5** | 88식 — 가이드와 일치 |
| →+K | 1 | 0 | 외식 굉부양 — 가이드와 일치 |
| →+P / ↘+P | 255 | 0 | 없음 — 가이드와 일치(쿄는 →+P 없음) |
| 공중 ↓+P | 4 | 0 | 나락떨구기 추정 |
| →↘↓↙←+P | 0 | 5(밀착) | 127식 팔청 — **늘 나가고 있었다.** 근접 전용 타격기라 원거리에선 헛침 (12장) |

- `0x09AD` 는 기술 고유 ID 가 아니라 **애니메이션 뱅크**다.
  ↓↘→+P 와 ↓↘→+K 가 둘 다 22 로 나온다. 기술 판별엔 데미지·위치와 함께 봐야 한다.

## 9. 다음 단계 제안

1. 캐릭터 ID·유파로 기술표를 고르는 구조만 먼저 세우고, **쿄 하나로 원버튼을 끝까지** 만든다
2. 되면 나머지 캐릭터 기술표를 채운다 (커맨드는 공개 자료 + 실측 검증)
3. 엔진은 SS2 의 `ss2sp.c` 를 거의 그대로 쓸 수 있다 — 리셋 트릭만 빼고,
   프레임 간격을 2~4 로 맞추면 된다

## 9. 캐릭터 ID 표 (실측, 0x08A0)

기본 18명 전원 확인. 숨김 8명은 미해금이라 빈 칸(255)으로 나온다.

| ID | 이름 | ID | 이름 | ID | 이름 |

| 0 | 쿄 | 6 | 이오리 | 12 | 켄 |
| 1 | 테리 | 7 | 하오마루 | 13 | 단 |
| 2 | 료 | 8 | 나코루루 | 14 | 사쿠라 |

## 11. 공중 보정 (완료)

처음엔 공중기가 대부분 「그냥 점프」로 뭉쳤다. 원인은 타이밍이 아니라 **지문이었다** —
점프 중 애니뱅크가 4/5 인데 공중기도 4/5 라 구분이 안 됐다.

**고친 방법: 애니 카운터(0x0C7E) 리셋을 발동 신호로 쓴다.**
새 동작이 시작되면 0으로 리셋되므로, 버튼 직후 4프레임 시점 값이 작으면 뭔가 나간 것이다.
여기에 **P1 Y(0x0930)** 를 더해 지상/공중을 분류한다.

부수 효과로 **지상 평타도 잡히게 됐다** — 뱅크가 255 그대로여도 카운터는 리셋되기 때문.
「뱅크 255 무리」 = 모션이 무효라 그냥 평타가 나간 커맨드들, 로 읽으면 된다.

결과: 공중 지문 112개(캐릭터당 4~9), 지상 지문 84개. 산출물 SWEEP2.txt

### 추가 오프셋
| 오프셋 | 뜻 | 값 |
|---|---|---|
| 0x0930 | **P1 Y** | 지상 128, 점프 정점 86 (사본 0x2440) |
| 0x0AB0 | P2 Y | 〃 |
| 0x0938 | P1 지면 높이 | 지상 24, 정점 66 (Y의 반전) |

점프 체공: U 누른 뒤 **약 10~45프레임**, 정점 25프레임.

## 12. 후속 실측 — 로컬 WSL2 (2026-08-27)

도구에 `!poke 오프셋=값` 을 추가하고 (svcrun.c), 램을 직접 써 가며 확정한 것들.

### ★ P1 체력 = 0x08AF · 0x08B3 (쌍)

- 피격 이벤트 때 **두 바이트가 동시에 같은 값으로** 깎인다. 읽기는 어느 쪽이든 된다.
- 실측 시계열 (광폭화 춘리에게 맞으며): 42→37→35→29→26→23
- poke 로 미리 값을 넣어도 다음 피격 때 정상 계산값으로 덮인다 → 쓰기는 의미 없음, 읽기 전용으로 쓸 것
- **최대치**: P1 쿄 42 (장기에프만 43, 나머지 17명 42) / CPU 춘리 48
  → CPU 가 보정을 받는 것으로 보인다 (BATTLE CONFIG 의 ADVANTAGE 로 추정, 미확인)
- 옛 후보 0x08D0/0x08D1 은 P2 구조체 상수였다 (P1 쪽 0x08B0/0x08B1 도 동일하게 48 고정)

### ★ KO 판정은 타격 이벤트 때만

- 체력을 poke 로 0 으로 만들어도 **아무 일도 안 일어난다.** 다음 타격이 들어와야 검사된다.
- P2 원본(0x0AE1)을 0 으로 만들어도 라운드가 안 끝나고 경기 계속.

### ★ CPU 필사 AI — 실측의 열쇠

- **P2 체력(0x0AE1)을 낮게 poke 하면 수동적이던 CPU 가 즉시 공격적으로 변한다.**
- 평상시 CPU 는 40초를 밀착해 있어도 안 때린다 (idle·밀기·점프압박 전부 무반응 실측).
- P1 이 맞는 상황이 필요한 실측은 전부 이걸로 만들면 된다: `!poke 0AE1=5`

### ★ 체력의 원본/사본 구조

- P2: 원본 **0x0AE1** (AI 블록 안, poke 지속·전파) → 표시 사본 0x08CF (poke 해도 매 프레임 복원)
- P1: 0x08AF/0x08B3 쌍이 이벤트 시점 동기 — 별도 원본이 더 있는지는 미확인 (읽기엔 무관)
- 참고: 0x08D3 은 P2 피해를 안 따라갔다. 5장의 「사본 0x08D3」 기록은 폐기.

### ★ 127식 팔청 — 오판 정정

- hcb+P 는 **원거리에서도 늘 발동하고 있었다** (뱅크 0). 헛치면 피해 0 이라 「미발동」으로 오판.
- 근접 전용 타격기: 밀착에서 피해 5. 간격 2·3·4 전부 발동, 마지막 ← 홀드 여부 무관.
- 판별 기준을 「뱅크 255 유지 = 미발동」으로 쓰면 안 된다. 뱅크 0 도 실기술이다.

### ★ 일반 잡기 발견 (전수조사 밖)

| 입력 (밀착) | 뱅크 | 비고 |
|---|---|---|
| ←+P | 2 | 뒤잡기 — 던지는 모션 확인 |
| →+P | 1 | 앞잡기 계열 (원거리 →+P 는 무기술) |

84종 전수조사는 시작 거리에서만 돌려서 밀착 전용 기술을 놓친다.
**캐릭터별 전수조사에 「240프레임 전진 후」 판을 추가할 것.**

### 추가 오프셋

| 오프셋 | 뜻 | 근거 |
|---|---|---|
| 0x08AF·0x08B3 | **P1 체력** (쿄 42, 장기에프 43) | 피격 시계열·선주입 덮임 |
| 0x0AE1 | **P2 체력 원본** | poke 지속·0x08CF 전파·필사 AI 발동 |
| 0x0B17 | 콤보 카운터 | 24 poke → 화면에 "24HITS!" |
| 0x08AC | 타이머 표시 문자 (ASCII) | 48('0')→32(' ') |
| 0x08BE / 0x08DE | P1/P2 유파 (구조체 간격 0x20) | poke 시 유파 아이콘 변화 |

### 구조체 배치

P1 블록 0x08A0~, P2 블록 0x08C0~ — **간격 0x20 평행**.
(캐릭터 ID 0x08A0/0x08C0, 유파 0x08BE/0x08DE, 체력 0x08AF·0x08B3/0x08CF·0x08D3 대응)
단 P2(CPU)의 진짜 체력 원본은 별도 AI 블록(0x0AD0~)에 있다.


## 13. svcsp v1 — 쿄 원버튼 엔진 가동 (2026-08-27)

`src/svcsp.c` — ss2sp.c 와 같은 구조의 SvC 전용 엔진. 롬 헤더(0x24 "SNKvsCAPCOM1")로
자동 판별해서 SvC 때만 입력을 받는다 (libretro.c 분기). SS2 경로는 손대지 않았다.

### 동작 방식

- 트리거 = X (또는 R). **SP + 방향** 으로 슬롯 선택 (ss2sp 와 같은 UX)
- 쿄 슬롯: 중립=황물기(236P) · 아래/↘=오니야키(623P) · 뒤=팔청(214P) ·
  앞=초필(236236P, 미검증) · ↙=난무형(미검증) · 공중=공중↓P
- 커맨드 주입: 방향 3프레임씩 → 마지막 방향 유지한 채 버튼 3프레임 (실측 규격)
- 다른 캐릭터는 아직 그냥 펀치 (기술표는 SWEEP2 로 채우면 된다)

### 엔진을 만들며 확정한 실측 (기존 기록 정정 포함)

| 발견 | 내용 |
|---|---|
| **애니 카운터의 정체** | 0x0C7E 는 「동작 진행도」가 아니라 **마지막 동작 시작 후 경과시계** — 2프레임에 1씩, 127에서 포화. 「대기=127」은 포화값이었다 |
| **평타 회복 = 12프레임** | §2 의 「40프레임 기다리면 나간다」는 과대. +12f(카운터 6)부터 정상 발동 |
| **이른 주입은 누출** | +6f(카운터 3~5) 주입은 **엉뚱한 기술**(뱅크 1)이 나간다. 행동가능 문턱 = 카운터 ≥6 |
| **뱅크 0 재확인** | 황물기 **꼬리**도 뱅크 0. 발동 성공 판정은 뱅크가 아니라 **카운터 감소(리셋)** 로 해야 한다 |
| **CPU 던지기** | 상대를 4초쯤 밀어붙이면 CPU 가 P1 을 던진다 (y=44 실측). 밀착 실험이 간헐적으로 깨지던 원인 |
| 전투중 판별 | char<18 · P2char<26 · style<3 · 1≤timer≤60 합성. Y 는 넣으면 안 된다(던져질 때 공중) |

### 회귀 시험 — tools/svc/sptest.py

빌드한 코어를 svcrun 으로 물려 **X 버튼 실발동**을 검사한다. 11종:
중립/아래/뒤/앞/공중/경직중/걷기×3/선택화면 무간섭/SS2 롬 불간섭.
현재 전부 통과. SS2 test_flow 20종도 통과.


### 강약과 렛카 (2026-08-27 추가 실측)

- **버튼 홀드 = 강.** 236P 를 3f 만 누르면 황물기(지속 ~24f), 16f 이상 잡으면
  **독물기**(지속 92f+, 전진 2.4배). 오니야키(623P)는 홀드 차이가 미미하다.
- **렛카 파생은 없다.** 황물기 히트 후 +12/20/30f 에 P·236P 재입력 전부 씹힘.
  평타조차 선행 모션 중엔 안 나간다. KOF 와 달리 강약 두 버전만 있는 구조.
- svcsp 반영: 트리거(X)를 잡고 있으면 버튼 스텝이 늘어난다(상한 20f).
  **X 탭 = 황물기, X 꾹 = 독물기.** ss2sp 의 sustain 과 같은 UX.
- 주의: c0_0 상태의 CPU 는 접근·정지 후 거리 118 로 후퇴하고 때때로 던진다.
  밀착 실측은 svc_f2.st (간격 62, 수동 CPU) 를 쓸 것.

## 14. 18캐릭터 기술표 투입 + K 버튼 검출 맹점 (2026-08-27)

- **기술표 전원 투입.** 웹 3원천 × SWEEP2 교차검증 → `moves.json` →
  `gen_svc_moves.py` → `svcsp_moves.h`. 표는 `MOVES.md`.
- **자동 검증 18/18** — `chartest.py`: 캐릭터별 세이브에서 중립X·아래X 실발동 확인.
  공중 3건(이오리·나코루루·춘리)은 점프 뱅크(4·5)와 겹치는 K 공중기라 판별 불가(미확정).
- **★ K 버튼 검출 맹점**: 애니 카운터 0x0C7E 는 **K(킥) 기술에 리셋되지 않는다.**
  K 실측은 뱅크(0x09AD)·피해로 봐야 한다. 옛 SWEEP 의 「그냥|K 포함 K 42종 전멸」은
  이 맹점의 오판 — K 기술표는 사실상 재조사 대상이다 (지문 기법을 뱅크 기반으로 바꿔서).
- 슬롯 원칙: D 에는 확정 대공(승룡권계), 게이지 초필은 F/DF. 켄·단·사쿠라·모리간 스왑 적용.
- 장기에프 회전잡기(360/720)는 632146 관용입력으로 성립 (실측).


## 15. 검수 완결 — K 카운터·POW 게이지·초필 전수 실발동 (2026-08-27)

### 새 오프셋 (전부 poke 검증)

| 오프셋 | 뜻 | 근거 |
|---|---|---|
| **0x0C7F** | P1 K(킥) 동작 카운터 | P/K 카운터는 버튼별 짝: 0x0C7E=P, 0x0C7F=K (사본 0x0C86/0x0C87) |
| **0x0963** | **P1 POW 게이지 원본** | poke 지속 + 하단 왼쪽 바 채움. 0x0965 는 표시용(서서히 따라옴) |
| **0x0AE3** | P2 POW 게이지 원본 | poke 지속 + 하단 오른쪽 바. 0x0AE5 표시용 |
| 0x08EF | 타이머 초당 프레임 카운터 | POW 아님 (poke 시 타이머 표시 반응) |

- **poke 로 채운 게이지는 자연 감쇠한다** (약 2/프레임, 바닥 56). 게이지 실험은
  반드시 **무입력 대조군과 같은 프레임을 비교**할 것 — 안 그러면 가짜 소모가 잡힌다.
- 초필 뱅크: 35(공통 난무·빔계), 27(샤이닝 크리스탈), 43(천렬각), 7(패산천승각), 21(무식)

### 검증 성적

- 일반 기술 105건 일괄: **88건 확정 승격** (K 카운터·뱅크·피해 판정)
- 초필 56건 대조군 재검: **51건 실발동 확정** (게이지 소모 증거)
- 불발 5건: 오토코미치·슌고쿠사츠·소닉허리케인·크로스파이어([4]646 계열)·크립틱니들
  → 게이지 소모 0. 표기 오류거나 올림픽 해금 전용 추정 — 가이드만 유지
- 남은 미검증: 공중 평타류(뱅크 무 — 동작 반응만 확인), 근접 커맨드 잡기(원거리 불발)
