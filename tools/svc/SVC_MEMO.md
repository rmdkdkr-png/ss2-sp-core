# SvC MotM 정찰 결과 (scratchpad 전용 — 커밋 안 함)

대상: SNK vs. Capcom MotM (NGPC), 한글패치 v17.2 (헤더 `SNKvsCAPCOM1`, 4MB)

## 1. 시험대

- 하네스 `svcrun.c` — 입력 스크립트 + 램/화면 덤프 + **상태 저장·복원**
  - 스크립트 문법: `<프레임> <버튼…>` / `!태그`(덤프) / `!save 파일` / `!load 파일`
  - 버튼: U D L R A B X Y ST SE  — **NGP A = 레트로 B**, NGP B = 레트로 A
- **전투 기준 상태 `svc_f2.st`** — 쿄(균형) vs 춘리, 도톤보리, 타이머 56
- 메뉴 경로: 타이틀 → 시작하기 → 메인메뉴(토너먼트) → 게임선택(싱글)
  → **유파선택(반격/균형/속공)** → 캐릭터선택 → VS → 스테이지 → 전투

## 2. ★ 원버튼은 된다 — 그리고 SS2 보다 쉽다

- **커맨드 주입으로 필살기가 나온다.** 236+A → 불꽃, 623+A → 상승기.
- **가로채기 문제가 없다.** SS2 의 핵심 난관이던 「찌꺼기가 긴 커맨드를 가로챔」이
  SvC 엔 없다. 네 가지로 확인:

  | 시험 | 결과 |
  |---|---|
  | 236 찌꺼기 남기고 → 623+A | **623+A 나감** (가로채기 없음) |
  | 236 찌꺼기 + 2f 후 → 623+A | 623+A 나감 |
  | 623 앞부분 남기고 → 236+A | 236+A 나감 |
  | 623 모션(버튼 없이) 후 → 236+A | 236+A 나감 |

  → **SS2 의 램 리셋 트릭이 필요 없다.** 입력만 넣으면 된다.

- **커맨드 입력 간격 창 = 2~4 프레임.**
  1프레임(너무 빠름) · 5프레임 이상(시간 초과) 은 실패. SS2 보다 창이 좁다.
- 직전 입력 찌꺼기(뒤로걷기·앞걷기·평타·아래·앞아래·웅크림)는 전부 정상 발동.
  실패했던 「B평타 직후」「점프 직후」는 **경직 때문**이었고 40프레임 기다리면 나간다.
  → 엔진은 「지금 행동 가능한가」만 보면 된다.

## 3. RAM 오프셋 (SYSTEM_RAM 16KB, CPU주소 = 0x4000 + 오프셋)

| 오프셋 | 뜻 | 값 | 근거 |
|---|---|---|---|
| `0x08A0` | **P1 캐릭터 ID** | 쿄=0, 테리=1, 켄=12 | 캐릭터 3종 교차검증 (사본 0x0882·0x096D) |
| `0x08BE` | **P1 유파** | 반격=0, 균형=1, 속공=2 | 유파 3종 전부 다른 값 (사본 0x096E) |
| `0x08CF` | **P2 체력** (최대 48) | 한 방에 48→47 | 체력바 오른쪽 끝과 일치 (사본 0x08D3) |
| `0x08EE` | 라운드 타이머 (10진) | 58/56/54 | 화면 숫자와 일치 |
| `0x092E` | P1 화면 X | | 입력 방향대로 R>무>L (사본 0x243E) |
| `0x0934` | P2 화면 X | 기준 94 | 카메라 스크롤 같이 탐 |
| `0x09AD` | P1 애니메이션 뱅크 | 236+A=22, 623+A=23, 지상평타·대기=255 | **발동 판정에 쓸 수 있다** |
| `0x0C7E` | P1 애니 카운터 | 동작 시작 0 → 증가, 대기 127 | 기술 종류와 무관 (사본 0x0C86) |

- **방향은 따로 안 찾아도 된다** — `P1X < P2X` 면 오른쪽. 커맨드 미러링엔 충분.
- 0x09AD 는 점프 중에도 255 가 아니다(=6). 「필살기 여부」로 쓰려면 지상 여부와 함께 봐야 한다.

## 4. 아직 못 한 것

- ~~P1 체력~~ — **해결 (12장).** 0x08AF·0x08B3 쌍. 0x08D0/0x08D1 은 상수(둘 다 아님).
- 기술 고유 ID (0x09AD 는 애니 뱅크라 기술마다 유일하지 않을 수 있음)
- 히트스톱 · 공중 판정
- 26명 기술표 (지금은 쿄 236/623 만 실측)


## 6. ABLE — 이 롬엔 없다 (실측 결론)

게임 내 BATTLE CONFIG 항목은 **DISP CUT / ADVANTAGE / PROVOKE / BUTTON / WINNING POINT**
다섯뿐이다 (유저 실기 확인). ABLE 같은 간이입력 설정은 없다.

혹시 유파가 커맨드를 간략화하는가 싶어 **세 유파 전부에서** 재봤다 — 아니다.

| 입력 | 반격 | 균형 | 속공 |
|---|---|---|---|
| ↓↘→+P (정식) | 발동 | 발동 | 발동 |
| →+P | — | — | — |
| ←+P | — | — | — |
| ↓+P | — | — | — |
| ↓+K | — | — | — |
| →+K | 특수기(굉부양) | 〃 | 〃 |

→ **간이 커맨드는 존재하지 않는다. 정식 커맨드만 먹는다.**
   FAQ 의 ABLE 열은 이 판본과 대응하지 않으므로 기술표 작성에 쓰지 않는다.
   버튼 배치는 **A=PUNCH, B=KICK** (게임 설정 화면 확인).

**뒤집어 보면 좋은 소식이다** — 이 게임엔 간이입력이 없으니
우리 원버튼 SP 가 대체재가 아니라 **이 게임 최초의 간이입력**이 된다.

## 7. 입력 규칙 (실측)

- **마지막 방향을 버튼보다 먼저 잡아야 한다.** →와 버튼을 같은 프레임에 넣으면 실패.
  방향을 2~4프레임 유지한 뒤, 그 방향을 **유지한 채로** 버튼을 누른다.
- 방향 간 간격 2~4프레임. 1프레임(너무 빠름)·5프레임 이상(시간 초과)은 실패.

## 8. 쿄 실측 표 (균형, 진행 중)

| 입력 | 0x09AD | 데미지 | 판정 |
|---|---|---|---|
| ↓↘→+P | 22 | 1 | 114식 황물기 — 가이드와 일치 |
| ↓↘→+K | 22 | 0 | 나가지만 빗나감 |
| ↘+K | 21 | **5** | 88식 — 가이드와 일치 |
| →+K | 1 | 0 | 외식 굉부양 — 가이드와 일치 |
| →+P / ↘+P | 255 | 0 | 없음 — 가이드와 일치(쿄는 →+P 없음) |
| 공중 ↓+P | 4 | 0 | 나락떨구기 추정 |
| →↘↓↙←+P | 0 | 5(밀착) | 127식 팔청 — **늘 나가고 있었다.** 근접 전용 타격기라 원거리에선 헛침 (12장) |

- `0x09AD` 는 기술 고유 ID 가 아니라 **애니메이션 뱅크**다.
  ↓↘→+P 와 ↓↘→+K 가 둘 다 22 로 나온다. 기술 판별엔 데미지·위치와 함께 봐야 한다.

## 9. 다음 단계 제안

1. 캐릭터 ID·유파로 기술표를 고르는 구조만 먼저 세우고, **쿄 하나로 원버튼을 끝까지** 만든다
2. 되면 나머지 캐릭터 기술표를 채운다 (커맨드는 공개 자료 + 실측 검증)
3. 엔진은 SS2 의 `ss2sp.c` 를 거의 그대로 쓸 수 있다 — 리셋 트릭만 빼고,
   프레임 간격을 2~4 로 맞추면 된다

| 1 | 테리 | 7 | 하오마루 | 13 | 단 |

## 11. 공중 보정 (완료)

처음엔 공중기가 대부분 「그냥 점프」로 뭉쳤다. 원인은 타이밍이 아니라 **지문이었다** —
점프 중 애니뱅크가 4/5 인데 공중기도 4/5 라 구분이 안 됐다.

**고친 방법: 애니 카운터(0x0C7E) 리셋을 발동 신호로 쓴다.**
새 동작이 시작되면 0으로 리셋되므로, 버튼 직후 4프레임 시점 값이 작으면 뭔가 나간 것이다.
여기에 **P1 Y(0x0930)** 를 더해 지상/공중을 분류한다.

부수 효과로 **지상 평타도 잡히게 됐다** — 뱅크가 255 그대로여도 카운터는 리셋되기 때문.
「뱅크 255 무리」 = 모션이 무효라 그냥 평타가 나간 커맨드들, 로 읽으면 된다.

결과: 공중 지문 112개(캐릭터당 4~9), 지상 지문 84개. 산출물 SWEEP2.txt

|---|---|---|
| 0x0930 | **P1 Y** | 지상 128, 점프 정점 86 (사본 0x2440) |
| 0x0AB0 | P2 Y | 〃 |

점프 체공: U 누른 뒤 **약 10~45프레임**, 정점 25프레임.

## 12. 후속 실측 — 로컬 WSL2 (2026-08-27)

도구에 `!poke 오프셋=값` 을 추가하고 (svcrun.c), 램을 직접 써 가며 확정한 것들.

### ★ P1 체력 = 0x08AF · 0x08B3 (쌍)

- 피격 이벤트 때 **두 바이트가 동시에 같은 값으로** 깎인다. 읽기는 어느 쪽이든 된다.
- 실측 시계열 (광폭화 춘리에게 맞으며): 42→37→35→29→26→23
- poke 로 미리 값을 넣어도 다음 피격 때 정상 계산값으로 덮인다 → 쓰기는 의미 없음, 읽기 전용으로 쓸 것
- **최대치**: P1 쿄 42 (장기에프만 43, 나머지 17명 42) / CPU 춘리 48
  → CPU 가 보정을 받는 것으로 보인다 (BATTLE CONFIG 의 ADVANTAGE 로 추정, 미확인)
- 옛 후보 0x08D0/0x08D1 은 P2 구조체 상수였다 (P1 쪽 0x08B0/0x08B1 도 동일하게 48 고정)

### ★ KO 판정은 타격 이벤트 때만

- 체력을 poke 로 0 으로 만들어도 **아무 일도 안 일어난다.** 다음 타격이 들어와야 검사된다.
- P2 원본(0x0AE1)을 0 으로 만들어도 라운드가 안 끝나고 경기 계속.

### ★ CPU 필사 AI — 실측의 열쇠

- **P2 체력(0x0AE1)을 낮게 poke 하면 수동적이던 CPU 가 즉시 공격적으로 변한다.**
- 평상시 CPU 는 40초를 밀착해 있어도 안 때린다 (idle·밀기·점프압박 전부 무반응 실측).
- P1 이 맞는 상황이 필요한 실측은 전부 이걸로 만들면 된다: `!poke 0AE1=5`

### ★ 체력의 원본/사본 구조

- P2: 원본 **0x0AE1** (AI 블록 안, poke 지속·전파) → 표시 사본 0x08CF (poke 해도 매 프레임 복원)
- P1: 0x08AF/0x08B3 쌍이 이벤트 시점 동기 — 별도 원본이 더 있는지는 미확인 (읽기엔 무관)
- 참고: 0x08D3 은 P2 피해를 안 따라갔다. 5장의 「사본 0x08D3」 기록은 폐기.

### ★ 127식 팔청 — 오판 정정

- hcb+P 는 **원거리에서도 늘 발동하고 있었다** (뱅크 0). 헛치면 피해 0 이라 「미발동」으로 오판.
- 근접 전용 타격기: 밀착에서 피해 5. 간격 2·3·4 전부 발동, 마지막 ← 홀드 여부 무관.
- 판별 기준을 「뱅크 255 유지 = 미발동」으로 쓰면 안 된다. 뱅크 0 도 실기술이다.

### ★ 일반 잡기 발견 (전수조사 밖)

| 입력 (밀착) | 뱅크 | 비고 |
|---|---|---|
| ←+P | 2 | 뒤잡기 — 던지는 모션 확인 |
| →+P | 1 | 앞잡기 계열 (원거리 →+P 는 무기술) |

84종 전수조사는 시작 거리에서만 돌려서 밀착 전용 기술을 놓친다.

## 13. svcsp v1 — 쿄 원버튼 엔진 가동 (2026-08-27)

`src/svcsp.c` — ss2sp.c 와 같은 구조의 SvC 전용 엔진. 롬 헤더(0x24 "SNKvsCAPCOM1")로
자동 판별해서 SvC 때만 입력을 받는다 (libretro.c 분기). SS2 경로는 손대지 않았다.

### 동작 방식

- 트리거 = X (또는 R). **SP + 방향** 으로 슬롯 선택 (ss2sp 와 같은 UX)
- 쿄 슬롯: 중립=황물기(236P) · 아래/↘=오니야키(623P) · 뒤=팔청(214P) ·
  앞=초필(236236P, 미검증) · ↙=난무형(미검증) · 공중=공중↓P
- 커맨드 주입: 방향 3프레임씩 → 마지막 방향 유지한 채 버튼 3프레임 (실측 규격)
- 다른 캐릭터는 아직 그냥 펀치 (기술표는 SWEEP2 로 채우면 된다)

### 엔진을 만들며 확정한 실측 (기존 기록 정정 포함)

| 발견 | 내용 |
|---|---|
| **애니 카운터의 정체** | 0x0C7E 는 「동작 진행도」가 아니라 **마지막 동작 시작 후 경과시계** — 2프레임에 1씩, 127에서 포화. 「대기=127」은 포화값이었다 |
| **평타 회복 = 12프레임** | §2 의 「40프레임 기다리면 나간다」는 과대. +12f(카운터 6)부터 정상 발동 |
| **이른 주입은 누출** | +6f(카운터 3~5) 주입은 **엉뚱한 기술**(뱅크 1)이 나간다. 행동가능 문턱 = 카운터 ≥6 |
| **뱅크 0 재확인** | 황물기 **꼬리**도 뱅크 0. 발동 성공 판정은 뱅크가 아니라 **카운터 감소(리셋)** 로 해야 한다 |

## 21. 히트 확인 체계 — 실플레이 제보 반영 (2026-08-28)

유저 실기 제보 두 건에서:

1. **스파링 타임 무한 = 타이머 255** — 전투 게이트(1~60)가 엔진을 통째로 재웠다.

## 27. ★ 좌우 인지 버그 — 좌표는 16비트였다 (2026-08-28, 유저 진단 적중)

## 28. 특수기 배치 제외 + A+B 실측 (2026-08-28)

- **특수기(command_normal)는 원버튼 배치 대상에서 제외** — 방향+버튼 한 번짜리는
  손으로 치면 된다 (유저 지적). 생성기가 엔진 표에서 거르고, 피커 목록에서도 사라짐.
  문서(moves.json·MOVES.md)에는 유지. 특수기가 유일한 공중기였던 캐릭터
  (쿄·이오리·나코루루·춘리·장기에프)의 AIR 슬롯은 비움 — 공중 X = 점프 공격.

- **A+B 동시 = 후방 회피(백플립)**, 이동 -35~40px, 게이지 +1~2.

## 29. ABLE 모드의 정체 — 세이브 해금 옵션 (2026-08-28)

유저가 JUE 변형 덤프 6종(base[!]/a1/h1/h2/t1/t2)을 확보, 타계정 바이너리 diff와 교차 검증.

- **변형판 정체**: 6종 모두 게임 코드는 100% 동일. 차이는 전부 카트리지 플래시
  세이브 섹터(0x1F8000/0x1FA000 이중화)뿐 → GoodTools [a]/[h]/[t] 딱지는 사실상
  "세이브가 구워진 채 덤프된 판". t2 는 a1 의 변경 1044바이트를 완전 포함(상위집합).
- **ABLE = アバレモード**: BATTLE CONFIG 문자열 테이블(0x024DE0~0x024E40)에서
  일어 항목명 나열(ゲージカクシ/チョウハツ/アバレモード/オーダーマスク/…)과 영문 나열

## 30. 기획 축소 — 약/강 버튼 분리 레이아웃 (2026-08-28)

- **결정(유저)**: 순정 ABLE(アバレ) 모드가 간이입력을 제공하므로(§29) 원버튼 모션

  헛침 — 리치 짧은 별개 모션으로 추정, 2회 재현 (약탭·5f이상은 정상 히트).

  약 기본기. 강은 Y·X 전용. 검증: 꾹 40f 데미지 3 유지, 신규 9/9, sptest 12.
- (속도 검증) 강기본기 히트 타이밍: 약 탭 12f, 강은 홀드 7~24f 어느 쪽이든 **24f 고정**
  — 발동은 누른 순간 시작되고 7f 시점에 약/강만 확정된다. 새 Y·X 탭도 24f = 순정 최속과

## 31. 정정 셋 — 글꼴·깨진 문자열·K 갈래 (2026-08-30)

토스트에 「벌읊기」가 **「벌 기」**로 떴다. 11px·8px 글꼴 양쪽에 **60자가 없었다.**

킥 계열 이름은 전부 깨져 있었다. 로마자 **F·I·J·K·M·Q·V·X·Z** 도 없어서
「(Kouryuken)」이 「(ouryuken)」이었다. 기술 이름은 메뉴에도 뜬다 — 유저가 읽는 글자다.

원인은 둘.

- 글꼴 생성기 `tools/gen_font.js` 와 갈무리 BDF 가 **저장소에서 사라져** 채울 수단이 없었다.
- `src/check_glyph.py` 가 못 걸렀다. 구멍이 셋이었다:
  ① 볼 파일을 손으로 적어둬서 SVC 쪽(`svcsp_moves.h`)이 목록에 아예 없었다.
  ② `ord(ch) > 0x7F` 라 **로마자를 안 봤다.**
  ③ 글꼴을 훑는 정규식이 글리프 항목과 **비트맵 행**을 구분 못 해, 행 값이 우연히
     글자 코드와 같으면 있는 것으로 쳤다.

조치 — 갈무리를 다시 받아(OFL 1.1, `~/ss2/font/`) `tools/gen_font.py` 를 새로 썼다.
파이썬으로 옮긴 이유는 노드 없이도 돌아야 해서다. **맞다는 증명은 이렇게 했다**:
BDF 에서 뜬 결과가 지금 헤더에 든 글자와 한 픽셀도 안 틀리는지 먼저 대조하고,
11px 908/908 · 8px 909/909 가 전부 일치할 때만 진행한다. 하나라도 어긋나면 멈춘다.
(원본 생성기가 **음수 x 픽셀을 버린다**는 것까지 맞춰야 「#」「j」가 일치했다.)
좁은꼴에 없는 한자는 보통꼴 `Galmuri11.bdf` 에서 뜬다 —「사치요 도리 (小夜千鳥)」용.
결과 969자/970자. 화면 확인 완료: 「벌읊기 →+P」 + 04 HITS.

검사기도 세 구멍을 다 막았다. 이제 디렉터리를 훑으므로 파일이 늘어도 따라간다.

### ② 「캔슬」 표시가 이중 인코딩으로 깨져 있었다

`svcsp.c` 의 화면 문자열 `svcsp_last_disp` 에 붙는 " 캔슬" 이
UTF-8 바이트를 Latin-1 로 착각해 한 번 더 인코딩된 상태였다. 화면엔 `ìºì¬` 로 나갔다.
되돌리는 법은 그 반대 — Latin-1 로 인코딩해서 UTF-8 로 다시 읽는다. 네 사본 모두 고쳤다.
이 글자(「캔」)는 글꼴에도 없었는데, 문자열이 깨져 있어서 **검사기가 필요한 줄도 몰랐다.**

### ③ ★ 125식 칠뢰 — K 갈래는 **있다**. 앞서 접은 것이 오판이었다

앞서 「파생 창에서 강킥·약킥을 넣어도 뱅크가 158 로 같다 → 이 판본에 3타 K 갈래가 없다」고
접었다. **틀렸다.** 뱅크 158 은 3타 파생의 **공용** 값이라 갈래를 못 가른다.
갈래는 P·K 카운터로 갈린다. 구상 입력 뒤 24f 에 3타를 넣고 프레임 단위로 본 결과:

| 3타 버튼 | 뱅크 | P 카운터(0x0C7E) | K 카운터(0x0C7F) | 콤보 | 피해 |
|---|---|---|---|---|---|
| 강펀치 | 158 | **0 으로 리셋 후 카운트업** | 127 (안 움직임) | 3→4 | 12→14 |
| 강킥   | 158 | 그냥 흐름 (리셋 없음) | **1 로 리셋 후 카운트업** | 3→4 | 12→14 |

같은 프레임(입력 +14f)에 각각 다른 카운터가 리셋된다 — **서로 다른 기술**이다.
피해·히트수는 같으므로 세기 이득은 없다. 넣는다면 이름·완성도 차원이다.

교훈: 뱅크만으로 K 기술을 판정하지 마라(§14 의 맹점이 여기까지 번졌다).
대조군도 함께 재라 — 3타를 안 넣은 시행이 콤보 3/피해 12 로 남는 것을 봐야
24f 의 4히트가 파생 때문임을 안다.

### ④ 배포 — 세 갈래 ABI

`Application.mk` 는 `APP_ABI := all` 로 **원래 전 ABI 를 만들고 있었는데**,
`build.gradle` 의 `abiFilters 'arm64-v8a'` 가 하나만 담고 있었다. 만들어 놓고 버린 셈.
`arm64-v8a` + `armeabi-v7a`(구형·32비트) + `x86_64`(에뮬·크롬북·WSA) 셋으로 넓혔다.
`x86`(32비트)와 `riscv64` 는 뺀다. APK v3.8(29), 1.96MB.

## 32. 칠뢰 탑재 · 3타 미히트는 남은 문제 (2026-08-30)

### 넣은 것 — 125식 칠뢰(K 갈래)

`svc_move` 에 **`next_k`** 를 더했다. 지금까지 `next`(탭)/`next_hold`(홀드) 둘뿐이라
「같은 자리에서 P 냐 K 냐」를 표현할 수가 없었다. 파생 창에서 **물리 킥 버튼**
(레트로패드 bit8 약킥·bit9 강킥)이 잡혀 있으면 `next_k` 로 간다.

창을 여는 조건도 `svc_chain_any()` 로 바꿨다. 예전 조건(`svc_chain_idx() >= 0`)으로 열면
킥에 손을 늦게 대는 갈래는 창이 아예 안 열린다 — 창은 갈래를 정하기 **전에** 열려야 한다.

검증: 트리거만 → 「외식 섬돌뚫기」, 강킥 유지 → 「125식 칠뢰」. 회귀 sptest 12 · chartest 18/18.

표에 넣을 때 커맨드를 비워 두면 생성기가 `if not seq: continue` 로 걸러낸다.
방향 없는 기술은 중립 `"5"` 를 준다 — 「개 추가타」가 이미 그 방식이다.

### 남은 문제 — 약 갈래 3타가 콤보에 안 붙는다

사슬은 **정확히 컴파일된다**(황물기 → 구상 → 섬돌뚫기/칠뢰). 그런데 히트가 안 는다:
강 갈래는 콤보 4·피해 16 인데 약 갈래는 콤보 3·피해 12 그대로다. 3타가 헛친다.

순정 입력으로 재 보면 **구상 트리거 +28f 부터** 붙는다(그 전엔 뱅크만 158 로 가고 히트 0):

| 구상 뒤 대기 | 콤보 | 피해 | 뱅크 |
|---|---|---|---|
| 0~24f | 3 | 12 | 156 |
| 28f 이상 | 4 | 14 | 158 |

**시도했다가 되돌린 것**: 파생 발사를 16f 늦추기(`SVC_CHAIN_MIN`). 되돌린 이유 셋 —
① 늦춰도 약 갈래는 여전히 안 붙었다. 타이밍만의 문제가 아니다.
② 「트리거를 잡고 기다린다」가 **「홀드 = 강 갈래」 규칙과 정면으로 부딪친다.**
   기다리려고 잡으면 갈래가 죄읊기로 넘어간다.
③ 불발 자동 재시도가 매크로 끝 +12f 에 끼어들어 `svc_compile` 로 파생 창을 지운다.
   지연을 넣으면 재시도가 먼저 이겨서 **파생 대신 시동기가 한 번 더** 나갔다.
   (재시도를 창 뒤로 미루는 우회를 넣어 봤지만, ①②가 남아서 통째로 걷었다.)

다음에 팔 곳은 타이밍이 아니라 **상대 상태**로 보인다. 강 갈래(죄읊기)는 상대를 오래
붙잡아 두는데 약 갈래(구상)는 회복이 빨라, 3타가 나갈 때 이미 상대가 경직에서 풀렸을 수 있다.
0x08F3(피격 경직)·0x09A7(히트스톱)을 3타 발사 순간에 같이 재 보면 갈릴 것이다.

- **캔슬 12명 불가**가 이번 최대 수확이자 최대 숙제다. 고치려면 주입을 빠르게 하거나
  (방향 스텝 압축), 캔슬 상황에서만 커맨드를 건너뛰고 기술을 직접 세우는 길이 필요하다.
  §19 의 「즉시 주입」 경로가 이미 있는데 **주입 자체가 느린 것**이 병목이다.
- 레오나·가일의 N 슬롯 기술은 접촉 거리에서 아예 안 맞는다 — 슬롯 배치를 다시 볼 것.

## 34. §33 캔슬 표 폐기 — 버튼을 잘못 눌렀다 (2026-08-31)

**§33 의 「기본기 → 기술 캔슬」 표와 「12명 캔슬 불가」 결론은 무효다.** 1152회 전부
엉뚱한 버튼으로 쟀다. 유저 제보(「뻔하게 캔슬 및 콤보가 되거든」)로 드러났고, 코드를 읽으니
유저가 맞았다.

### 원인 — 대본의 `A` 는 펀치가 아니라 **킥**이다

대본 문자는 레트로패드 기준이고 코어가 NGP 로 바꾼다(§0 에도 적혀 있었다:
「NGP A = 레트로 B」). 현재 코어의 리맵은 `svcsp.c:589-604`:

| 대본 키 | libretro 비트 | 실제 |
|---|---|---|
| `B` | bit 0 | **약펀치** (NGP A) |
| `A` | bit 8 | **약킥** (NGP B) |
| `Y` | bit 1 | **강펀치** |
| `X` | bit 9 | **강킥** |
| `R1` | bit 11 | 기술키 |

`spcombo.py` 는 `NORMS = [('약','2 A'), ('강','14 A')]` 였다 — **전부 약킥**이다.
게다가 「강」도 만들어진 적이 없다: 약 버튼은 `svcsp.c:598-599` 에서 **6프레임에서 강제
해제**된다("꾹 눌러도 강이 안 된다"). 강은 별도 버튼 Y/X 다.

※ 배치가 둘이다. `svcsp_frame_app()`(`svcsp.c:806`)은 `svc_native_basics=1` 로 순정 통과
(탭 약 / 홀드 강)지만 코어가 부르는 진입점은 `svcsp_frame` 이라 **현재 빌드는 리맵판**이다.
§26 이 `16 B` 로 강펀을 냈던 것은 그 이전 층위다.

### 하필 그 버튼이 쿄의 캔슬을 원천 봉쇄한다

`svcsp.c:561` — `dud = cancel_dud && attack_was_kick`. `cancel_dud` 는 **쿄만 1**.
킥으로 치면 `pending_kind=4` 로 빠져 **평타 +40프레임이 지나야** 쏜다(킥 캔슬창의 지정기가
누에잡기 = 비공격기라서 일부러 피하는 것, §24). 펀치면 `kill_cancel` — 대기 0프레임.

**실측 (쿄, 정지 상대, SP 는 노멀 4프레임 뒤)**

| 노멀 | 노멀 히트 | 기술 히트 | 간격 | 콤보 |
|---|---|---|---|---|
| 약펀 | 4f | 30f | 26f | **연결** |
| 강펀 | 18f | 44f | 26f | **연결** |
| 약킥 | 8f | 56f | 48f | 끊김 |
| 88식(↘K) | 4f | 78f | 74f | 끊김 |

주입 지연도 §33 이 3배 부풀렸다. `STEP_FRAMES=2` 라 236 계열은 **방향 6프레임 뒤 버튼,
총 9프레임**이다. 캔슬 창 8프레임에 충분히 들어간다.

### 바로잡은 실측 (기준선 보정)

다타 노멀이 있어 「콤보 ≥ 2」로는 못 센다(88식은 그 자체가 2타). **노멀 단독 기준선보다
타수가 늘어야** 캔슬로 센다.

| 노멀 | 단독 | 캔슬 |
|---|---|---|
| 약펀·강펀·앉약펀·앉강펀 | 1타 | **전부 연결** (0~24f) |
| 약킥·앉약킥 | 1타 | 안 됨 (dud 회피) |
| 강킥·앉강킥 | 1타 | 연결 — 경직이 길어(피해 7) 40f 회피 뒤에도 닿는다 |
| 88식 | 2타 | 안 됨 |
| 굉부양 | 1타 | 안 됨 (단독일 때는) |

### 캔슬 계층 — 기본기 → 특수기 → 필살기

유저 지적: 「88식은 **기본기 캔슬 후 발동일 때만** 이어서 필살기로 캔슬이 됐다」.
특수기 단독에서 SP 를 누르는 것은 애초에 성립하지 않는 순서다. 3단으로 다시 재니:

**쿄 4타 콤보 (정지 상대, 좌우 동일) — 2880회 실측**

| 루트 | 타수 | 간격 |
|---|---|---|
| 약펀 → 굉부양 → SP | **4타** | 시동 6f, SP 4f |
| 강펀 → 굉부양 → SP | **4타** | 24f, 4f |
| 앉강펀 → 굉부양 → SP | **4타** | 24f, 4f |
| 기본기 → 특수기 (SP 없이) | 3타 | — |
| 기본기 → **88식** → SP | 안 이어짐 | 88식이 킥이라 dud 회피 |

특수기 중 **굉부양(→K)만** 필살기로 이어진다. 가드 상대(상단방어)는 전 조합 0~1타,
SP 연결 0회 — §19 의 「가드·헛침에서는 캔슬 불가」 그대로.

### 곁가지 — 러시(자동콤보) 제거

유저 지시로 `svcsp.c` 의 러시 사다리를 껐다(`svc_rush_on = 0`). 약 기본기를 24프레임 창
안에 연타하면 **3타째에 버튼을 P↔K 로 갈아치우고 4타째에 필살기를 자동 발사**하던 기능이다.
손으로 치는 콤보를 엔진이 덮어써서 「누른 대로 안 나간다」가 된다.
약펀 6연타에 compile 0회로 확인. 되살리려면 그 한 줄을 1 로.

### 남은 것

- 18캐릭터로 확대 (쿄에서 성립한 조합만 추려서)
- **점프 시동 콤보는 저장소에 실측이 아예 없다** — 점프강 → 서서강 구간이 미개척
- 손 커맨드 대조군(엔진 끄고 직접 236P)과의 타수 차이 = 엔진이 잃는 양

도구: `tools/svc/spcombo.py` (쿄 / 특수기 모드), `tools/svc/mkspar.py` (시험대 굽기).

## 36. 점프 시동 콤보 — 8타 / 피해 26, 그리고 판정 확정 (2026-08-31)

「점프 기본기 → 서서 기본기」는 저장소에 실측이 **아예 없던** 구간이었다. 3갈래 병렬
실측 19,214회 + 확인 실측 약 11,000회로 열었다.

### 판정 확정 — 0x0B17 은 표시 타이머가 아니다

병렬 실측 중 한 갈래가 「콤보 카운터(0x0B17)는 표시용 타이머지 콤보 판정이 아니다,
212건 중 34건이 거짓양성」이라고 주장했다. §33~§35 가 전부 이 잣대 위에 서 있으므로
그냥 넘길 수 없어 **반증 실험**을 했다.

약펀 → g프레임 → 약펀 (둘 다 확실히 맞는 간격만 본다):

| 간격 g | 최대 카운터 | 총피해 | 해석 |
|---|---|---|---|
| 18·20f | 1 | 3 | 한 대만 맞음 |
| **22·24f** | **2** | 5 | 두 대 다 맞음 — 라이트 체인 창 |
| **26~40f** | **1** | **5** | **두 대 다 맞았는데 카운터는 1** |

**두 대가 다 맞아도 이어지지 않으면 카운터가 1에 머문다.** 거짓양성이 아니다.
`0x0B17` 은 게임 자신의 콤보 판정이고, §33~§35 의 수치는 그대로 유효하다.
(주의: 강펀으로는 이 시험이 안 된다 — 밀려나서 두 번째가 안 닿는다. 약펀으로 할 것.)

**라이트 체인 창 = 22~25f.** 26f 부터는 그냥 두 번 때린 것이다.

### 점프 기초 (처음 잰 것)

```
p1y  128 → 119(8f) → 105(12f) → 90(18f) → 85(24f 정점) → 99(34f) → 128(42f 착지)
```
체공 42프레임, 정점 24프레임 부근.

**전진 점프는 거리가 전부다.** 접촉 세이브(`svc_ct_*`)에서 전진 점프하면 66px 날아가
**상대를 지나쳐 전부 0타**다. 맞는 구간은 p1x 100~149, 4버튼 모두 맞는 곳은 110~139.
`svc_spar_정지_0.st`(p1x=120)가 정확히 한가운데다.
제자리 점프는 접촉 거리에서 맞는다 — 시동으로는 이쪽이 쉽다.

공중공격이 맞는 시점(제자리, 접촉거리): 강펀 16~28f · 강킥 16~26f · 약펀 20~32f ·
약킥 16~32f. 착지 후 연결폭은 **공중 강펀 d1=24~28 이 가장 넓다**.

|---|---|---|---|

**정리**: 8타/26 은 이론 최대이고 프레임 단위 정확도가 필요하다. 실전 권장은 **6타/20**.
점프 시동은 잘 맞으면 2타·피해 6 을 더하지만, 그 대가가 1프레임 정확도 두 자리다.
