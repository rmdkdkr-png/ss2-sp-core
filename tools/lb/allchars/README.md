# 월화 SP 전 캐릭터 — 코어 4.05

포켓코어 앱 v4.04에서 코어만 업데이트하는 배포입니다. 앱 APK를 다시 설치할 필요가 없습니다.

숨김 5명과 각성 카에데를 포함한 15개 캐릭터 상태를 지원합니다. ROM과 플래시 저장 영역은 쓰지 않고, 대전 RAM의 방향 이력만 입력합니다. 잠긴 캐릭터를 강제로 해금하지 않습니다.

SP + 방향으로 아래 기술을 고릅니다. 앞/뒤는 캐릭터가 바라보는 방향 기준입니다. A=베기, B=발차기, AB=동시입력, [4]/[2]=모으기. 숫자는 키패드 방향(2=아래, 4=뒤, 6=앞, 8=위)입니다. 화면의 A+B와 패드 L은 계속 동시입력입니다.

리·잔테츠·카가미의 공중 SP는 점프 높이를 확인하고 발동합니다. 상승 초기에 누르면 최대 20프레임 안에서 적정 높이까지 기다립니다. 각성 카에데의 공중기는 수동 입력으로 필살기임을 입증하지 못해 비워 두었습니다. 초필살기와 모든 파생기 자동 연속입력은 이번 범위에 포함하지 않습니다. 파생은 기존 A/B 입력을 사용합니다.

## 검증

- 실제 Windows libretro 코어에서 79개 배치 × 좌우 2방향 × 입력 위상 2종 × 20회 = 6,320/6,320. 지상 기술은 수동 입력 동작 전이를 기준으로 비교했습니다.
- 각 캐릭터에서 세이브를 다시 불러오지 않고 중립 SP 5회: 75/75.
- SP 끔: 15개 캐릭터에서 이전 코어와 RAM·화면 차이 없음.
- 입력 6,144조합, 링 머리 128위치의 쓰기 범위, 누르고 있을 때 재발동 방지, 잘못된 캐릭터 ID, 공중 대기 입력의 스테이트 리셋 검사 통과.
- 다른 6개 게임 동일 상태 부팅/입력 검사: 화면과 안정 RAM 동일. SvC 소리는 같은 기준 코어끼리도 변동하여 판정에서 제외. 다른 5개는 소리도 동일.
- Android arm64-v8a / armeabi-v7a / x86_64 빌드 성공. Android 실기 플레이 검수는 하지 않았습니다.

게임 내에서 정상 선택한 기본 9명을 대조하고, 숨김 캐릭터 시험은 별도 테스트 상태에서 선택 확정 ID를 지정한 뒤 게임 자체 대전 초기화로 생성했습니다. 배포 코어에는 이 시험용 ID 쓰기가 없습니다.

## 적용

포켓코어 업데이트 확인 → 코어 4.05 다운로드 → 게임을 완전히 종료한 뒤 다시 실행합니다. 사용자 폴더 PocketCore/cores에 수동 설치한 svc 코어가 있으면 그 파일이 우선하므로 새 코어로 교체해야 합니다.

### 측정 재현

Python ctypes/Pillow/numpy와 수정 전 baseline.dll, 수정 후 allchars.dll을 이 폴더에 준비하고, LB_ROM 환경변수에 보유한 원본 UE ROM 경로를 설정합니다. prepare.py → rings.py 0 15 → stress.py → off.py 순서입니다. ROM·플래시·세이브는 저장소에 배포하지 않습니다. regression.py의 다른 게임 경로는 자신의 보유 ROM 경로로 바꾸어야 합니다.
