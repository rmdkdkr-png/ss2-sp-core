# 격투게임 입력 메커니즘 해부 — 공통 절차

원버튼 필살기(SP 키)를 어느 게임에 붙이든 **그 게임의 입력 규칙부터 해부해야 한다.**
SvC 에서 그 과정을 다 밟았고, 거기서 나온 절차와 함정을 게임과 무관하게 정리한다.
새 게임(SS2 · 월화 · 환세취호전 …)에 붙일 때 이 순서대로 하면 된다.

핵심 원칙 하나: **우리 코어가 만든 결과를 게임의 규칙으로 착각하지 마라.**
리맵·보정이 얹힌 상태로 재면 그건 우리 코드를 재는 것이다. 반드시 **우회 경로**를 먼저
만들고(예: `SVCSP_OFF=1`) 순정 상태에서 규칙을 뽑은 뒤, 그 규칙 위에 코어를 얹는다.

---

## 0. 준비물

| 것 | SvC 에서 | 새 게임에서 할 일 |
|---|---|---|
| 하네스 | `tools/svc/svcrun` (libretro 코어 + 대본 + RAM 관측 CSV) | 그대로 쓴다. 관측 주소만 바꾼다 |
| 대본 문법 | `<프레임> <버튼들>` / `!load` `!save` `!w` `!poke` / `!태그`(RAM·화면 덤프) | 공통 |
| 순정 우회 | `SVCSP_OFF=1` | 코어에 **같은 스위치를 먼저 만들어라** |

---

## 1. 주소 찾기

찾을 것은 다섯이다. 없으면 아무것도 못 잰다.

| 주소 | 찾는 법 | SvC 값 |
|---|---|---|
| **콤보 카운터** | 확실한 콤보를 내고 값이 오르는 바이트. 화면의 「N HITS」와 대조 | `0x0B17` |
| 상대 체력 | 때리고 줄어드는 바이트. **표시 사본과 원본이 따로 있다** | 표시 `0x08CF` |
| 동작 ID(뱅크) | 기술마다 다른 값. 대기값이 있다(SvC 255) | `0x09AD` |
| 위치 | 걸으면 변하는 16비트 | P1 `0x0934` |
| 방향 이력 | 방향을 바꿔 가며 덤프를 diff. 일정 간격으로 값이 밀린다 | `0x0CB8~0x0CCE`(2바이트 간격) |

**요령**: 「같은 상태 두 번 덤프」로 **저절로 흔들리는 바이트를 먼저 제외**한다(SvC 는 224개).
그다음 조건만 바꿔 diff 하면 후보가 수십 개로 준다.

---

## 2. 잣대를 **반증**해라

주소를 찾았다고 믿지 마라. **명백히 아닌 경우를 만들어 값이 안 오르는지** 확인한다.

> SvC 예: 약펀 → g프레임 → 약펀. g=22~24f 는 카운터 2(체인), **g=26~40f 는 두 대가 다
> 맞아도 카운터 1**. 그래서 `0x0B17` 은 표시 타이머가 아니라 진짜 콤보 판정이다.

이 반증을 안 하면 잣대가 죽은 줄 모르고 수천 회를 버린다(실제로 두 번 버렸다).

---

## 3. 시험대 만들기

**아케이드 세이브는 못 쓴다.** CPU 가 반격한다(SvC: 무입력 320프레임에 체력 42→28,
위치 140→95→184). 반드시 **연습/스파링 모드의 허수아비**로.

절차 (`tools/svc/mkspar.py` 가 SvC 판):
1. 부팅 → 연습 모드 진입 시퀀스를 스크립트로 재현
2. 설정에서 **적 동작 = 정지**(허수아비) / **가드**(대조군) 를 고른다
3. 캐릭터 선택 화면에서 **상태를 저장**해 두고 재사용 → 부팅 1회로 전 캐릭터를 굽는다
4. **접촉 상태까지 구워 둔다** — 매 시행마다 걸어가면 느리고 흔들린다
5. 방향 반전판은 **뛰어넘어서** 만든다(가드 상대는 물러나므로 구석에 몰고 넘는다)

⚠️ **거리를 poke 로 맞추지 마라.** 위치 주소는 표시 사본이라 값은 박히는데 판정에는
안 쓰인다(SvC: 150~330 전 구간 무피해, 걸어가면 피해 3). **걸어서** 만든다.

## 4. 입력 규격 뽑기 (순정 상태에서)

여기가 본론이다. 네 가지를 순서대로 잰다.

### (1) 버튼 대응
각 물리 키를 짧게 눌러 무엇이 나오는지. **대본 문자 ≠ 게임 버튼**이다.
> SvC: 대본 `B`=약펀 `A`=약킥 (레트로패드 기준이라 뒤집혀 있다)

### (2) 약/강 문턱
커맨드를 넣고 **버튼 잡는 길이를 1프레임씩** 늘린다.
> SvC: 1f 안 나감 · **2~7f 약** · **8f 이상 강**. 경계 7|8

가르는 잣대는 **전진 거리**가 제일 깨끗하다(SvC 약 0~2px vs 강 27~28px). 피해도 갈린다.

### (3) 커맨드 창 — 버튼을 언제 누르나
버튼 시점을 마지막 방향 기준으로 **음수까지** 쓴다.
> SvC: 방향과 **같은 프레임은 실패**(다른 기술) · **+2~+5f 성공** · +6f 부터 만료
> 마이너스는 「선입력 유예」가 아니다 — **모션이 끝나는 순간 눌려 있으면** 되는 것이다.
> 긴 홀드가 마이너스에서 통하는 이유가 그것뿐이다.

### (4) 방향 스텝 길이
각 방향을 몇 프레임씩 넣어야 인식되나. **하나씩** 줄여 본다(전부 줄이면 안 된다).
> SvC: 마지막 두 칸은 2프레임을 지켜야 하고 그 앞만 1프레임 가능.
> 줄여도 **기술이 빨라지지는 않는다** — 주입이 기술 발생에 흡수된다.

## 5. 기술표 채우기

슬롯·모션·버튼 말고 **파생(렛카)** 을 반드시 판다. 없으면 「기술 콤보가 안 나간다」가 된다.

찾는 법: 기술을 낸 뒤 후속 입력 네 가지를 넣고 **뱅크가 새 값으로 바뀌고 콤보가 느는지**.
- 같은 커맨드 + P / 같은 커맨드 + K / 버튼만 P / 버튼만 K
- 간격은 10·20·30프레임 정도로 훑고, 되는 곳만 촘촘히

> SvC 에서 이렇게 4개를 새로 찾았다(이오리 3연격, 마이, 펠리시아, 사쿠라).
> **문서의 산문 notes 에 이미 적혀 있었다** — 구조화가 안 돼 있었을 뿐이다.
> 새 게임에서도 **기존 메모부터 훑어라.**

## 6. 함정 목록 (전부 실제로 밟은 것)

| 함정 | 증상 | 피하는 법 |
|---|---|---|
| 코어 리맵을 게임 규칙으로 착각 | 「강은 별도 버튼」 같은 잘못된 결론 | 순정 우회 스위치로 먼저 잰다 |
| 아케이드 세이브 | 수치가 흔들리고 재현이 안 됨 | 연습 모드 허수아비 |
| 위치 poke | 값은 박히는데 판정 무효 | 걸어서 만든다 |
| **표본을 입력 뒤에만 찍음** | 앞쪽 히트를 통째로 놓침(7타 루트가 피해 3으로 나왔다) | **입력 사이사이에** 찍는다 |
| **뱅크를 안 봄** | 다른 기술이 나가는데 피해가 같아 못 알아챔 | 판정에 **항상 뱅크를 넣는다** |
| 다타 기본기 | 「콤보 ≥2」가 거짓양성 | **단독 기준선 대비 증가**로 판정 |
| 슬롯은 앞/뒤, 패드는 좌/우 | 방향 반전에서 전부 오발로 찍힘 | face 를 보고 물리 방향을 뒤집는다 |
| 이름 부분일치 | 「A 2타」가 「A」를 가리킴 | 정확 일치를 먼저 찾는다 |

## 7. 코어에 얹을 때

순정 규칙을 뽑았으면 **그대로 옮기는 것**이 원칙이다. 추측을 넣지 마라.

> SvC 예: 게임의 약/강 문턱이 8프레임인데 엔진은 `trig_len >= 5` 로 추측해 9프레임을
> 채우고 있었다. 근거 없는 5 때문에 사람의 탭(3~8f)이 약과 강으로 갈렸다.
> **사용자가 누른 길이를 그대로 게임 버튼 길이로 옮기면** 경계가 저절로 맞는다.

보정을 넣을 때는 **그 보정이 다른 상황을 망치지 않는지** 반드시 같이 잰다.
> SvC 예: 「방향 이어받기」는 터치의 어긋남을 구제하려던 것인데 걷던 방향까지 물어왔다.
> 지우지 말고 **조건을 좁혀라**(잡고 있던 길이로 가름).
