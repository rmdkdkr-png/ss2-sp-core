# tools/kof — KOF R-2 하네스·검증기 (이식소)

KOF R-2 한글패치와 SP 원버튼 엔진 이식에 쓰는 것들. **다른 방도 집어 쓰라고 여기 둔다** —
`RELEASE_RULES.md` §1 의 「릴리즈 전 자동 자」가 이 파일들을 가리킨다.

## ngprun.c — libretro 하네스

RetroArch 없이 코어를 직접 물려 대본대로 돌린다.

```
cc -O2 -o ngprun ngprun.c -ldl
./ngprun <core.so> <rom> <대본> <출력접두사>
```

대본 한 줄: `<프레임> <버튼…>` · `!<태그>`(램 16KB + PPM 덤프) · `!save f` / `!load f` ·
`!poke <hex>=<십진>` · `!w <태그> <오프셋[:w],…>`(매 프레임 CSV) · `!vram <태그>`
버튼은 레트로패드 문자 — **NGP A = 레트로 `B`, NGP B = 레트로 `A`**.

**끝에 소리를 찍는다** — 최대 진폭과 「소리 난 프레임 수」.
화면 검증은 사운드 회귀를 못 잡는다. KOF R-2 v0.2 가 10바이트로 소리가 통째로 죽었는데
메뉴 순회 화면 30장이 **바이트 단위로 같았다.** 그래서 넣었다.

### ⚠ DEFAULTS 를 코어가 읽는 키 전체와 대조할 것

RetroArch 가 없으니 코어 옵션을 하네스가 먹인다. 빠뜨린 옵션의 처리가 **코어마다 다르다** —
대개 `if (조회성공 && var.value)` 라 무해한데 지오메트리 둘이 예외다:

| 옵션 | 안 주면 | 결과 |
|---|---|---|
| `ngp_svcsp_band` | 코어가 `int on = 1` 로 **켠다** | 높이 152 → 184 |
| `ngp_ss2sp_sides` | 코어 초기값이 `true` | 폭 160 → 288 |

빠진 키 찾기: `grep -o '"ngp_[a-z0-9_]*"' libretro.c | sort -u` 로 뽑아 DEFAULTS 와 맞춰 본다.

### ⚠ 대본에서 `!` 로 시작하는 줄은 주석이 아니다
첫 낱말을 태그로 먹어 파일이 생긴다. 대본에 주석을 넣지 마라.

### `NGP_OPTS` — 코어 옵션 덮어쓰기

```
NGP_OPTS="ngp_ss2sp=enabled,ngp_svcsp_engine=enabled" ./ngprun …
```

**회귀에는 이게 필수다.** 기본값이 `ngp_ss2sp=disabled` 라 코어의 **입력 분기 블록이
통째로 안 돈다** — 그 상태로 「출력이 같다」를 재면 아무것도 안 재고 있는 것이다.
엔진 켬/끔 대조군도 이 스위치로 만든다.

## m1_reg.py — 게임 간 무회귀 (잡음을 실측으로 빼고 본다)

같은 `.so` 를 **두 번** 돌려 스스로 재현 안 되는 바이트를 먼저 찾고,
**양쪽 코어에서 모두 안정한 바이트**에 대해서만 두 코어를 비교한다.

```
python3 m1_reg.py <기준코어.so> <새코어.so> [대본]
```

왜 필요한가 — 이 코어는 **호스트 시각을 읽는다**(`mednafen/ngp/rtc.c` 의 `time()`).
그래서 SVC 는 실행마다 램 9바이트, SS2 는 3바이트가 흔들린다.
그걸 모르고 재면 **내 변경과 무관한 차이를 회귀로 오독한다** — 실제로 한 번 그럴 뻔했다.

⚠ **SS2 는 콜드 부팅 후 약 1,200프레임까지만 결정적이다.** 그 뒤로는 같은 코어끼리도
화면이 24,000바이트씩 갈린다. 회귀 대본은 그 창 안에서 끝내라(`m1_reg.txt` 가 그렇다).

## test_kofsp.c — 에뮬레이터 없는 단위 시험

```
cc -O1 -I../../src -o test_kofsp test_kofsp.c ../../src/kofsp.c && ./test_kofsp
```

롬 판별 진리표와, M1 의 약속인 **「kofsp_frame 이 순정 폴드와 완전히 같다」**를
`pad`×`(Y,X,L,R)` 4,096조합 전수로 확인한다.
**에뮬로는 이 둘을 구별할 수 없다 — 출력이 같기 때문이다.** 그래서 따로 잰다.

## kof_tables.py — 오프셋 표 불변식

**릴리즈 전 관문.** 원본에서 「모든 항목이 `base+오프셋` 에서 문자열 시작을 가리키는」
표를 찾아 두고, 패치본에서 그 표가 **여전히 성립하는지** 묻는다.

```
python3 kof_tables.py find  <원본롬>            표 후보 찾기
python3 kof_tables.py check <원본롬> <패치롬>    패치가 표를 깼는지
```

KOF R-2 v0.2 는 `0x10BA0C`(17항목)의 **마지막 두 칸**을 덮어
`.NOT DAMAGE`·`.EXIT` 대신 `POWER`·`EQUIP` 한복판을 가리키고 있었다.
그 메뉴를 여는 사람만 깨진 글자를 보므로 **화면 순회로는 영원히 안 걸린다.**

**음성 대조군을 먼저 봐라** — 깨진 판에서 빨간불이 뜨는 것을 확인한 뒤에 쓴다.
그러지 않으면 「초록」이 「아무것도 안 재고 있음」과 구별되지 않는다.

⚠ **문자열 앞 모드바이트 집합은 게임마다 다시 잡아야 한다.**
KOF R-2 는 `0x0A`(가타카나)·`0x0B`(히라가나)·`0x07`. 소스 위쪽 `MODE` 를 고쳐 쓴다.

## 지금까지 잰 것 (2026-09-02, 스파링 정지무대·쿄·위상 2종)

| 기호 | 값 | 성질 |
|---|---|---|
| `OFF_ACT` | `0x0D3C` | 동작번호. 서기 213 · 탭 57 · 홀드 173 · 236계 96 · 623계 127→7→63 |
| `OFF_FACE` | `0x0D4A` | **bit7** 이 반전. 평시 P1=0 / P2=129 |
| `OFF_Y1` / `OFF_H1` | `0x0D50` / `0x0D58` | 화면 Y(지상 128) / 지면 위 높이(지상 24). 합이 152인 **거울** |
| `OFF_VX` | `0x0D5A` | 16비트. 앞 +6553 / 뒤 −6553 (소수부) |
| `OFF_HP2` | `0x0EC1` | 상대 체력. 히트한 **그 프레임에** 준다 |
| `OFF_HOLDCNT_P/K` | `0x100C` / `0x100D` | 버튼 쥠. 2f 당 1, 놓으면 리셋 |
| `OFF_ANIM_P/K` | `0x1014` / `0x1015` | 동작 경과. 2f 당 1, **127 포화**. `0x101C/D` 에 짝 |
| `OFF_COMBO` | `0x10ED` | 콤보. **반증 통과**(≥38f 간격이면 둘 다 맞아도 0) |
| P2 블록 | **P1 + `0x140`** | P1 act `0x0D3C` ↔ P2 act `0x0E7C` |

| 상수 | 값 | |
|---|---|---|
| `KOFSP_HOLD_STRONG` | **6프레임** | 카운터 3. **SVC 는 12였다 — 재사용 금지** |
| `KOFSP_TAP_MAX` | **4프레임** | 5프레임은 **위상에 따라 갈림 → 금지구역** |
| `KOFSP_HIST_CLEAR` | **12프레임** | 찌꺼기 만료 |
| `KOFSP_ACT_HITSTUN` | **76** | 상대 act 가 이 값 = 히트 |

**★ 방향 이력 링은 없다.** SVC 는 `0x0CB8~` 에 24칸 링이 있어 커맨드를 직접 써 넣어
발동을 9→3프레임으로 줄였다. KOF R-2 엔 **그런 것이 없다** — 프레임마다 램 16KB 를
48프레임 전량 떠서 확인했다(`kof_ring.py`): 시프트 관계 **0쌍**, 시스템 대역에서
변하는 주소 **12개뿐**, 원형 버퍼 후보 **0개**.
→ 링 주입 대신 **매크로 전에 방향이 조용한 12프레임을 확보**한다(+12프레임 지연).

**★ 찌꺼기는 막는 게 아니라 이어 붙는다.** `R,D` 뒤에 `D,DF,R+B` 를 넣으면
합쳐서 `R,D,D,DF,R` 이 되어 **623 이 먼저 완성**된다. 그래서 물어야 할 것은
「가로채나」가 아니라 「언제 만료되나」였고, 답이 12프레임이다.

## ★ 흡수 3종 — 긴 커맨드가 짧은 것에 먹힌다

act 카탈로그(`kof_catalog.py`)로 전수를 훑다가 **지문이 같은 짝**이 셋 나왔다.
게임의 인식기가 **먼저 완성되는 것**을 내기 때문이다.

| 넣은 것 | 실제로 나간 것 | 어디서 |
|---|---|---|
| `41236` | **`236`** | 전 캐릭터 (끝이 `236`) |
| `63214` | **`214`** | 전 캐릭터 (끝이 `214`) |
| `2141236`(초필) | **`236`** | **카스미만** |

→ **슬롯에 긴 커맨드를 태우지 마라.** 태우면 실패가 「안 나갔다」가 아니라
  **「다른 게 나갔다」**로 나와 판정이 통째로 흐려진다.
→ 같은 뿌리의 현상이 **찌꺼기 이어붙음**이다: `R,D` 뒤에 `D,DF,R` 을 넣으면
  합쳐서 `R,D,D,DF,R` 이 되어 **623 이 먼저 완성**된다(만료 12프레임).
→ SVC 의 「오의 열진참 421 이 호월참으로 흡수」와 같은 계보다. 게임이 바뀌어도 **먼저 물어라**:
  「안 나간 것인가, 이웃에 먹힌 것인가」 — 시계열 act 지문으로만 갈린다.

## 회귀는 한 명령이다 — `kof_regress.py`

```
python3 kof_regress.py <새코어.so> <기준코어.so> [--quick] [--trials N]
```

0층 문지기 → 1층 단위 → 2층 무회귀(6게임) → 3층 발동률 → 4층 누출.
실측 소요: `--quick` **1.1분**.

**0층이 왜 맨 앞인가** — **낡은 바이너리로 잰 초록은 초록이 아니다.**
코어 `.so` 가 `src/*.c` 보다 낡았으면 **거부하고 멈춘다.**
이 방에서 두 번 물렸다: 빌드 직후 회귀가 옛 `.so` 를 잡은 것, 그리고 다른 방의 러너가
`[ -x 파일 ] || gcc` 가드 탓에 **몇 주 동안 재컴파일을 안 해** 화면 색이 물빠진 채로 나간 것.
(만들자마자 내 것도 잡았다 — 소스를 고치고 코어를 안 구운 상태였다.)

## 원칙 하나

**「이 자리가 정말 그것인가」를 롬이 스스로 답하게 만들어라.**
겉모습은 증거가 아니다 — KOF R-2 에서 가나 대역(0xA1~0xDF) 바이트를 「안 옮긴 일본어」로
보고 **실행 코드와 오프셋 표**를 덮었다(14자리 29바이트). 화면에도 소리에도 안 걸렸다.
