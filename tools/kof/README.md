# tools/kof — KOF R-2 하네스·검증기 (이식소)

KOF R-2 한글패치와 SP 원버튼 엔진 이식에 쓰는 것들. **다른 방도 집어 쓰라고 여기 둔다** —
`RELEASE_RULES.md` §1 의 「릴리즈 전 자동 자」가 이 파일들을 가리킨다.

## ngprun.c — libretro 하네스

RetroArch 없이 코어를 직접 물려 대본대로 돌린다.

```
cc -O2 -o ngprun ngprun.c -ldl
./ngprun <core.so> <rom> <대본> <출력접두사>
```

대본 한 줄: `<프레임> <버튼…>` · `!<태그>`(램 16KB + PPM 덤프) · `!save f` / `!load f` ·
`!poke <hex>=<십진>` · `!w <태그> <오프셋[:w],…>`(매 프레임 CSV) · `!vram <태그>`
버튼은 레트로패드 문자 — **NGP A = 레트로 `B`, NGP B = 레트로 `A`**.

**끝에 소리를 찍는다** — 최대 진폭과 「소리 난 프레임 수」.
화면 검증은 사운드 회귀를 못 잡는다. KOF R-2 v0.2 가 10바이트로 소리가 통째로 죽었는데
메뉴 순회 화면 30장이 **바이트 단위로 같았다.** 그래서 넣었다.

### ⚠ DEFAULTS 를 코어가 읽는 키 전체와 대조할 것

RetroArch 가 없으니 코어 옵션을 하네스가 먹인다. 빠뜨린 옵션의 처리가 **코어마다 다르다** —
대개 `if (조회성공 && var.value)` 라 무해한데 지오메트리 둘이 예외다:

| 옵션 | 안 주면 | 결과 |
|---|---|---|
| `ngp_svcsp_band` | 코어가 `int on = 1` 로 **켠다** | 높이 152 → 184 |
| `ngp_ss2sp_sides` | 코어 초기값이 `true` | 폭 160 → 288 |

빠진 키 찾기: `grep -o '"ngp_[a-z0-9_]*"' libretro.c | sort -u` 로 뽑아 DEFAULTS 와 맞춰 본다.

### ⚠ 대본에서 `!` 로 시작하는 줄은 주석이 아니다
첫 낱말을 태그로 먹어 파일이 생긴다. 대본에 주석을 넣지 마라.

## kof_tables.py — 오프셋 표 불변식

**릴리즈 전 관문.** 원본에서 「모든 항목이 `base+오프셋` 에서 문자열 시작을 가리키는」
표를 찾아 두고, 패치본에서 그 표가 **여전히 성립하는지** 묻는다.

```
python3 kof_tables.py find  <원본롬>            표 후보 찾기
python3 kof_tables.py check <원본롬> <패치롬>    패치가 표를 깼는지
```

KOF R-2 v0.2 는 `0x10BA0C`(17항목)의 **마지막 두 칸**을 덮어
`.NOT DAMAGE`·`.EXIT` 대신 `POWER`·`EQUIP` 한복판을 가리키고 있었다.
그 메뉴를 여는 사람만 깨진 글자를 보므로 **화면 순회로는 영원히 안 걸린다.**

**음성 대조군을 먼저 봐라** — 깨진 판에서 빨간불이 뜨는 것을 확인한 뒤에 쓴다.
그러지 않으면 「초록」이 「아무것도 안 재고 있음」과 구별되지 않는다.

⚠ **문자열 앞 모드바이트 집합은 게임마다 다시 잡아야 한다.**
KOF R-2 는 `0x0A`(가타카나)·`0x0B`(히라가나)·`0x07`. 소스 위쪽 `MODE` 를 고쳐 쓴다.

## 원칙 하나

**「이 자리가 정말 그것인가」를 롬이 스스로 답하게 만들어라.**
겉모습은 증거가 아니다 — KOF R-2 에서 가나 대역(0xA1~0xDF) 바이트를 「안 옮긴 일본어」로
보고 **실행 코드와 오프셋 표**를 덮었다(14자리 29바이트). 화면에도 소리에도 안 걸렸다.
